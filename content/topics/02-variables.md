## 학습 목표

- `let`과 `const`를 사용해 변수와 상수를 선언할 수 있다.
- 블록 스코프와 함수 스코프의 차이를 설명할 수 있다.
- `var`를 권장하지 않는 이유(호이스팅)와 TDZ를 설명할 수 있다.

## JavaScript 문법 학습 기준
- ECMAScript 2015 (ES6) 이후의 문법을 기준으로 설명
- 권장 스타일 가이드: [JavaScript Standard Style](https://standardjs.com/rules-kokr.html)

## 변수 작성 규칙

### 식별자(변수명) 작성 규칙
- 반드시 **문자, 달러(`$`) 또는 밑줄(`_`)** 로 시작
- **대소문자를 구분**
- **예약어 사용 불가** – `for`, `if`, `function` 등

> 📝 **예약어**: 프로그래밍 언어가 문법을 위해 미리 예약해둔 특별한 단어들 (ex: for, if, function, …)

> 📌 **TIP**
> - 의미가 드러나는 이름을 사용하여 데이터의 의미를 명확히 설명하세요. (ex: `userName`, `phoneNumber`)
> - `$` 나 `_`로 시작하는 변수는 특별한 용도(DOM 선택, 내부용 변수)로 쓰이니, 일반 변수와 구분하세요.

> ⚠️ **헷갈리기 쉬운 점** — `_name`, `$user`는 **사용 가능**합니다. 숫자로 시작하거나 예약어(`function`, `for`, `if`)인 경우만 안 됩니다.

### 식별자(변수명) Naming Convention

| 표기법 | 사용처 | 예 |
|---|---|---|
| 카멜 케이스 (`camelCase`) | 변수, 객체, 함수 | `userName` |
| 파스칼 케이스 (`PascalCase`) | 클래스, 생성자 | `Member` |
| 대문자 스네이크 케이스 (`SNAKE_CASE`) | 상수(constants) | `MAX_COUNT` |

> 📝 **상수(constants)**: 한 번 선언하면 값을 바꿀 수 없도록 잠가버리는 특별한 변수

> 📌 **TIP**
> - 문법이 아닌 '소통'의 규칙임으로 소통 도구임을 이해해야 합니다.
> - 가장 중요한 것은 **'일관성'** 이고, 팀의 스타일 가이드를 따르는 것이 우선입니다.

## 변수 선언 키워드

### 변수 선언 키워드 3가지
1. `let` – 재할당이 필요한 변수를 선언할 때 사용
2. `const` – 재할당이 불가능한 상수를 선언할 때 사용
3. ~~`var`~~ – 재선언/재할당이 가능하고, 현재는 **호이스팅(Hoisting) 문제로 사용을 권장하지 않음**

| 키워드 | 재할당 | 재선언 | 스코프 | 도입 |
|---|---|---|---|---|
| `let` | **O** | X | 블록 스코프 | ES6 |
| `const` | **X** | X | 블록 스코프 | ES6 |
| `var` | O | **O** | **함수 스코프** | ES6 이전 |

### let – 블록 스코프(block scope)를 갖는 지역 변수를 선언
1. **재할당 가능**
2. 재선언 불가능
3. ES6에서 추가

```js
let number = 10  // 1. 선언 및 초기값 할당
number = 20      // 2. 재할당
```
```js
let number = 10  // 1. 선언 및 초기값 할당
let number = 20  // 2. 재선언 불가능
```

### const – 블록 스코프(block scope)를 갖는 지역 변수를 선언
1. **재할당 불가능**
2. 재선언 불가능
3. ES6에서 추가

```js
const number = 10  // 1. 선언 및 초기값 할당
number = 10        // 2. 재할당 불가능
```
```js
const number = 10  // 1. 선언 및 초기값 할당
const number = 20  // 2. 재선언 불가능
const number       // SyntaxError
```

> 💡 **쉽게 이해하기** — `const number` 처럼 값 없이 선언만 하면 SyntaxError입니다. 정리: **const는 선언 시 반드시 초기화해야 합니다.** (`let`은 `let y` 처럼 선언만 해도 되고, 값은 `undefined`)

> 💡 **재할당 vs 재선언**
> - **재할당**: 이미 만든 변수에 `=`로 새 값을 넣는 것 → `number = 20`
> - **재선언**: 같은 이름으로 변수를 또 만드는 것 → `let number = 20` (한 번 더)

### 블록 스코프 (block scope)
- `if`, `for`, 함수 등의 **'중괄호(`{}`) 내부'** 를 가리킴
- 블록 스코프를 가지는 변수는 **블록 바깥에서 접근 불가능**

```js
// js_variable.html
let x = 1
if (x === 1) {
  let x = 2
  console.log(x)  // 2
}
console.log(x)  // 1
```

> 💡 **쉽게 이해하기** — 중괄호 `{}`를 **방**이라고 생각하세요. 방 안에서 `let x = 2`로 만든 x는 방 안에서만 보이는 **다른 변수**입니다. 그래서 방 밖의 `x`는 여전히 1입니다.

> 📌 **TIP**
> - 스코프 안에서 `let`으로 선언하면 밖에서 접근할 수 없습니다.
> - `var`는 블록을 무시하고 함수 단위로 작동해 파이썬과 비슷합니다. 가급적 사용하지 않는 것을 권장합니다.

### 어떤 변수 선언 키워드를 사용해야 할까?
- **"const를 기본으로 사용할 것"**
  - 코드의 의도 명확화
    - 해당 변수가 재할당되지 않을 것임을 명확히 표현
    - 개발자들에게 변수의 용도와 동작을 더 쉽게 이해할 수 있게 해줌
  - 버그 예방
    - 의도치 않은 변수 값 변경으로 인한 버그를 예방
    - 큰 규모의 프로젝트나 팀 작업에서 중요
- **필요한 경우에만 `let`으로 전환 (재할당이 필요한 경우)**
  - `let`을 사용하는 것은 해당 변수가 의도적으로 변경될 수 있음을 명확히 나타냄
  - 코드의 유연성을 확보하면서도 `const`의 장점을 최대한 활용할 수 있음

> 📝 **서술형 대비** — "기본적으로 const를 사용해 재할당되지 않음을 명확히 하고 의도치 않은 값 변경으로 인한 버그를 예방하며, 재할당이 필요한 경우에만 let을 사용한다."

## var (참고)

### var – ES6 이전에 변수 선언에 사용했던 키워드
- 재할당 가능
- 재선언 가능
- **함수 스코프(function scope)** 를 가짐
- **"호이스팅"** 되는 특성으로 인해 예기치 못한 문제 발생 가능
  - 선언하기 전 사용할 수 있음
- 변수 선언 시 `var`, `const`, `let` 키워드 없이 대입하면 전역 변수처럼 동작하므로 **절대 사용하지 않음**

### 함수 스코프 (function scope)
- 함수의 중괄호 내부를 가리키고, 함수 스코프를 가지는 변수는 함수 바깥에서 접근 불가

```js
function foo() {
  var x = 1
  console.log(x) // 1
}
console.log(x) // ReferenceError: x is not defined
```

> 💡 **쉽게 이해하기** — `var`는 **함수의 중괄호만** 벽으로 인정합니다. `if`나 `for`의 중괄호는 벽으로 보지 않습니다. 반대로 `let`/`const`는 **모든 중괄호**를 벽으로 인정합니다(블록 스코프).

## 호이스팅 (참고)

### 호이스팅(hoisting)이란?
> 📝 **호이스팅**: 코드가 실행되기 전, 변수 및 함수 선언문이 스코프의 최상단으로 끌어올려지는 듯한 현상

### 모든 선언은 호이스팅 된다.
- `var`, `let`, `const`, `function`, `class` 등 **모든 선언은 호이스팅 됨**
- 다만, **'초기화'가 함께 이루어지느냐**에 따라 동작 방식과 에러 발생 여부가 달라짐

### 변수의 생성 단계와 호이스팅 차이
- 자바스크립트 엔진은 변수를 **선언(Declaration) → 초기화(Initialization) → 할당(Assignment)** 단계로 생성
- 호이스팅은 이 단계 중 **어디까지 진행되느냐**가 핵심

1. **var의 호이스팅 (선언 + 초기화 동시 진행)**
   - 동작: 스코프 최상단에서 선언과 동시에 `undefined`로 초기화됨
   - 결과: 변수 선언 문장 이전에 접근해도 에러가 나지 않고 `undefined`를 반환
   ```js
   console.log(name)  // undefined (에러발생 X)
   var name = '홍길동'
   ```
   > ⚠️ 이 코드를 브라우저(연습장)에서 그대로 실행하면 `undefined` 대신 빈 문자열이 찍힙니다. 브라우저에는 원래 `name`이라는 전역 값이 있어서 겹치기 때문이니, 직접 확인할 땐 변수 이름을 `userName` 등으로 바꿔 보세요. 시험에서는 **`undefined`** 가 답입니다.
2. **let, const의 호이스팅 (선언만 진행)**
   - 동작: 스코프 최상단으로 선언(이름 등록)은 되지만, 실제 코드 라인에 도달하기 전까지 초기화(메모리 할당)는 되지 않음
   - 결과: 초기화되지 않은 상태에서 접근하려 하므로 참조 에러(ReferenceError)가 발생
   ```js
   console.log(age)  // ReferenceError: Cannot access 'age' before initialization
   let age = 30
   ```
   - ※ 만약 호이스팅이 아예 되지 않았다면 `age is not defined` (정의되지 않음) 에러가 떠야 하지만, 엔진이 변수의 존재는 알고 있기 때문에 **initialization 관련 에러** 발생

> 💡 **쉽게 이해하기 – 단계로 보는 호이스팅**
>
> | | ① 선언 | ② 초기화 | ③ 할당 | 선언 전에 접근하면 |
> |---|---|---|---|---|
> | `var` | 맨 위로 | 맨 위에서 `undefined` | 그 줄에서 | `undefined` |
> | `let` / `const` | 맨 위로 | **그 줄에 도달해야** | 그 줄에서 | ReferenceError (TDZ) |
> | 함수 선언식 | 맨 위로 | 맨 위에서 | 맨 위에서 (함수 전체) | 정상 호출 |
>
> 에러 메시지로 구분하기: **"Cannot access … before initialization"** = 호이스팅은 됐지만 TDZ, **"… is not defined"** = 아예 선언된 적 없음.

### 일시적 사각지대 (TDZ, Temporal Dead Zone)
- 스코프의 시작 지점부터 변수의 **초기화가 이루어지는 지점(실제 코드 선언부)까지의 구간**
- TDZ 참고 링크: [MDN – let의 TDZ](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/let#temporal_dead_zone_tdz)

> 📌 **TIP**
> - `let`, `const`, `class`는 호이스팅이 되지만 이 TDZ에 갇혀 있기 때문에, 선언 전에 접근할 수 없습니다.
> - 이는 개발자의 실수를 방지하는 안전장치 역할을 합니다.

### 함수 선언식의 호이스팅
- 함수 선언식(`function a() {}`)은 `var`보다 더 강력하게 호이스팅 됨
- 선언, 초기화, 할당(함수 본체)이 모두 동시에 최상단으로 끌어올려지므로, **선언 전에도 함수를 문제없이 호출**할 수 있음

```js
sayHello() // 'Hello!' 출력

function sayHello() {
  console.log('Hello!')
}
```

### 호이스팅 요약 비교

| 키워드 | 호이스팅 여부 | 초기화 시점 | TDZ | 비고 |
|---|---|---|---|---|
| `var` | O | 스코프 진입 시 (undefined) | X | 선언 전 접근 가능 (권장 X) |
| `let` / `const` | O | 실제 코드 선언 줄 도달 시 | O | 선언 전 접근 불가 (안전) |
| `function` | O | 스코프 진입 시 (함수 전체) | X | 선언 전 호출 가능 |
| 함수 표현식 | O | 실제 코드 선언 줄 도달 시 | O | const로 선언하면 let, const 규칙을 따름 (선언 전 호출 불가) |
| `class` | O | 실제 코드 선언 줄 도달 시 | O | 선언 전 사용 불가 |

### 출력 결과 예측 연습

```js
console.log(a)
var a = 1

console.log(b)

```

## 세미콜론 (참고)

### 세미콜론 (semicolon)
- 자바스크립트는 문장 마지막 세미콜론(`;`)을 **선택적으로 사용 가능**
- 세미콜론이 없으면 **ASI**에 의해 자동으로 세미콜론이 삽입됨
  - ASI (Automatic Semicolon Insertion, 자동 세미콜론 삽입 규칙)
- JavaScript를 만든 Brendan Eich 또한 세미콜론이 선택적이어야 한다고 생각 (세미콜론을 강제하지 않는 스타일을 선호)

> 📌 **TIP** — 세미콜론의 사용 여부보다 중요한 것은 **'일관성'** 입니다. 팀의 스타일 가이드를 따르는 것이 우선입니다.

## 핵심 정리
- JavaScript에서 변수를 선언할 때는 세 가지 키워드를 사용할 수 있음
  - `let`: 재할당이 가능한 변수를 선언함 (블록 스코프를 가짐)
  - `const`: 재할당이 불가능한 상수를 선언하며, 선언 시 반드시 초기화해야 함 (블록 스코프를 가짐)
  - `var`: 재선언 및 재할당이 가능하고 함수 스코프를 가지고, 호이스팅 문제로 **현재는 사용을 권장하지 않음**
- 기본적으로 `const`를 사용하고, 재할당이 필요한 경우에만 `let`을 쓰는 것이 좋음
- 모든 선언은 호이스팅되지만, `let`/`const`/`class`는 TDZ 때문에 선언 전에 접근할 수 없음
