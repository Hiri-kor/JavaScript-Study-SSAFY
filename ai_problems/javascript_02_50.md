## [파트 1] 객체 기초 및 속성 조작 (1~6번)

**1. JavaScript의 객체(Object) 구조에 대한 설명으로 틀린 것은?**
① 중괄호(`{}`)를 이용해 작성한다.
② 중괄호 안에는 `key: value` 쌍으로 구성된 속성(property)을 여러 개 작성할 수 있다.
③ `key`에는 문자열과 숫자 자료형이 모두 그대로 유지되며 저장된다.
④ `value`에는 함수를 포함한 모든 자료형이 허용된다.

**2. 다음과 같은 객체가 선언되어 있을 때, `'key with space'` 속성의 값에 접근하는 올바른 방법은?**
```js
const user = {
  name: 'Alice',
  'key with space': true
}
```
① `user.key with space`
② `user.'key with space'`
③ `user['key with space']`
④ `user[key with space]`

**3. 객체 `user`에서 `name` 속성을 완전히 삭제하기 위해 사용하는 올바른 구문은?**
① `user.name = null`
② `delete user.name`
③ `remove user.name`
④ `user.pop('name')`

**4. 객체의 속성 존재 여부를 확인하는 `in` 연산자에 대한 설명으로 옳지 않은 것은?**
① `'greeting' in user`와 같은 형태로 사용한다.
② 객체의 키뿐만 아니라 배열의 인덱스 존재 여부도 확인할 수 있다.
③ 객체 자신이 직접 가진 속성만 확인하며, 상속받은 속성은 무시한다.
④ 상속받은 속성을 제외하고 자기 속성만 확인하려면 `Object.hasOwn(obj, key)`를 사용하는 것이 좋다.

**5. 객체들이 기능을 물려받는 원본(부모 역할) 객체를 가리키며, 자신에게 없는 속성을 부모, 조상 순으로 찾아가는 메커니즘과 관련된 용어는?**
① 콜백 체인 (Callback Chain)
② 프로토타입 체인 (Prototype Chain)
③ 스코프 체인 (Scope Chain)
④ 옵셔널 체이닝 (Optional Chaining)

**6. 다음 코드의 실행 결과로 출력되는 값은?**
```js
const person = { name: 'Alice' }
person.age = 30
person.name = 'Bella'
console.log(person.name, person.age, person.job)
```
① `'Alice' 30 undefined`
② `'Bella' 30 undefined`
③ `'Bella' 30 null`
④ `Uncaught ReferenceError` 발생

## [파트 2] 메서드와 `this` 키워드 (7~13번)

**7. JavaScript의 메서드(Method)에 대한 설명으로 가장 적절한 것은?**
① 객체 외부에서 선언되어 객체를 인자로 받는 모든 함수이다.
② 객체 속성에 정의된 함수로, `object.method()` 방식으로 호출한다.
③ 메서드 내부에서는 같은 객체의 다른 속성에 접근할 수 없다.
④ 메서드를 정의할 때는 반드시 화살표 함수를 사용해야 한다.

**8. JavaScript의 `this` 키워드에 대한 설명으로 올바른 것은?**
① 함수가 선언(정의)될 때 가리키는 대상이 영구적으로 결정된다.
② 어떤 방식으로 함수를 호출하든 항상 전역 객체(`window`)를 가리킨다.
③ 함수를 '호출하는 방법'에 따라 가리키는 대상이 달라진다.
④ 화살표 함수는 일반 함수보다 더 독립적인 자신만의 `this`를 생성한다.

**9. 브라우저 환경에서 다음과 같이 일반 함수를 단순 호출했을 때 `this`가 가리키는 대상은?**
```js
const myFunc = function () {
  return this
}
console.log(myFunc())
```
① `undefined`
② `myFunc` 함수 자신
③ 전역 객체 (`window`)
④ `null`

**10. 다음 코드에서 `myObj2.myFunc()`를 호출했을 때 콘솔에 출력되는 `this`에 대한 설명으로 옳은 것은?**
```js
const myObj2 = {
  numbers: [1, 2, 3],
  myFunc: function () {
    this.numbers.forEach(function (number) {
      console.log(this)
    })
  }
}
myObj2.myFunc()
```
① `myObj2`가 3번 출력된다.
② `numbers` 배열이 3번 출력된다.
③ `forEach`의 콜백 함수는 일반 함수로 호출되었기 때문에 전역 객체(`window`)가 3번 출력된다.
④ 문법 에러가 발생한다.

**11. 10번 문제의 코드에서 `forEach` 내부의 `this`가 `myObj2`를 가리키도록 해결하는 가장 적절한 방법은?**
① `forEach` 대신 `map`을 사용한다.
② `forEach`의 인자로 전달하는 콜백 함수를 화살표 함수(`(number) => { ... }`)로 작성한다.
③ `myFunc` 자체를 화살표 함수로 변경한다.
④ `console.log(this)` 대신 `console.log(myObj2.this)`를 사용한다.

**12. 화살표 함수에서의 `this` 동작 원리로 올바른 것은?**
① 화살표 함수는 자신만의 `this`를 가지지 않고, 한 단계 상위(외부) 스코프의 `this` 값을 가져와 참조한다.
② 화살표 함수 내부에서는 `this` 키워드를 아예 사용할 수 없다.
③ 화살표 함수의 `this`는 항상 호출한 배열 요소를 가리킨다.
④ 화살표 함수의 `this`는 무조건 `document` 객체를 가리킨다.

**13. JavaScript에서 `this`가 호출 방식에 따라 동적으로 결정됨으로써 얻는 장점은?**
① 코드 실행 속도가 2배 빨라진다.
② 메모리 누수를 자동으로 방지한다.
③ 함수(메서드)를 하나만 만들어 여러 객체가 공유하여 각자 자신의 데이터로 동작하게 할 수 있다.
④ 개발자가 실수할 가능성이 완전히 사라진다.

## [파트 3] JSON과 추가 객체 문법 (14~24번)

**14. JSON(JavaScript Object Notation)에 대한 설명으로 틀린 것은?**
① Key-Value 형태로 이루어진 자료 표기법이다.
② JavaScript의 객체와 유사한 구조를 가진 "문자열(string)"이다.
③ JavaScript 전용 데이터 형식으로, Python이나 Java 등 다른 언어에서는 사용할 수 없다.
④ JavaScript에서 JSON 데이터를 조작하려면 Object 자료형으로 변환해야 한다.

**15. JavaScript 객체를 JSON 형식의 문자열로 변환하는 메서드(A)와, JSON 문자열을 다시 JavaScript 객체로 변환하는 메서드(B)가 바르게 짝지어진 것은?**
① (A) `JSON.parse()` / (B) `JSON.stringify()`
② (A) `JSON.stringify()` / (B) `JSON.parse()`
③ (A) `Object.toJSON()` / (B) `JSON.toObject()`
④ (A) `JSON.encode()` / (B) `JSON.decode()`

**16. 다음 코드에서 적용된 ES6 추가 객체 문법 2가지는 무엇인가?**
```js
const name = 'Alice'
const user = {
  name,
  greeting() {
    return 'Hello'
  }
}
```
① 계산된 속성, 구조 분해 할당
② 단축 속성, 단축 메서드
③ 전개 구문, 옵셔널 체이닝
④ 프로토타입 상속, 콜백 함수

**17. 다음 코드와 같이 대괄호(`[]`)를 이용해 변수의 값이나 표현식의 결과를 객체의 키로 동적 생성하는 문법의 명칭은?**
```js
const prefix = 'my'
const suffix = 'property'
const bag = {
  [prefix + suffix]: 'value'
}
```
① 단축 속성 (Shorthand property)
② 계산된 속성 (Computed property name)
③ 구조 분해 할당 (Destructuring assignment)
④ 옵셔널 체이닝 (Optional chaining)

**18. 객체 구조 분해 할당(Destructuring assignment)에 대한 설명으로 옳은 것은?**
① 객체의 속성을 변수에 할당할 때 변수 이름은 임의로 자유롭게 지어도 원래 속성값이 순서대로 들어간다.
② 함수의 매개변수 자리에서는 구조 분해 할당을 사용할 수 없다.
③ `const { firstName, email } = userInfo`처럼 객체의 키 이름과 동일한 변수명으로 속성을 쉽게 추출할 수 있다.
④ 구조 분해 할당을 수행하면 원본 객체의 해당 속성들은 모두 삭제된다.

**19. 다음 코드의 실행 결과로 콘솔에 출력되는 `newObj`의 모습은?**
```js
const obj = { a: 2, c: 3, d: 4 }
const newObj = { ...obj, a: 1, e: 5 }
console.log(newObj)
```
① `{ a: 2, c: 3, d: 4, e: 5 }`
② `{ a: 1, c: 3, d: 4, e: 5 }`
③ `{ obj: { a: 2, c: 3, d: 4 }, a: 1, e: 5 }`
④ 중복된 키 `a`로 인해 `SyntaxError` 발생

**20. 전개 구문(`...`)을 이용한 객체 복사의 특징인 '얕은 복사(Shallow Copy)'의 의미로 가장 정확한 것은?**
① 객체의 속성 중 문자열만 복사하고 숫자는 복사하지 않는 것
② 최상위 속성(겉)만 새로운 객체로 복사하고, 내부의 중첩 객체(속)는 주소값을 공유하는 복사
③ 복사본의 최상위 원시값 속성을 변경하면 원본 객체의 속성도 함께 바뀌는 복사
④ 객체의 키(Key)만 복사하고 값(Value)은 모두 `undefined`로 초기화하는 복사

**21. 다음 코드의 출력 결과로 올바른 것은?**
```js
const profile = { name: 'Alice', age: 30 }
console.log(Object.entries(profile))
```
① `['name', 'age']`
② `['Alice', 30]`
③ `[['name', 'Alice'], ['age', 30]]`
④ `{'name': 'Alice', 'age': 30}`

**22. Optional chaining(`?.`) 연산자의 동작 방식으로 틀린 것은?**
① `?.` 앞의 평가 대상이 `null` 또는 `undefined`이면 에러를 발생시키지 않고 평가를 멈춘 뒤 `undefined`를 반환한다.
② 중첩된 객체의 속성에 안전하게 접근할 때 `&&` 연산자를 반복해서 쓰는 것을 대체할 수 있다.
③ 체인 중간이 `null`인 경우 그 뒤의 코드는 실행되지 않는데, 이를 '단락 평가'라고 부른다.
④ `obj?.prop`와 `obj?.[prop]`는 사용할 수 있지만, 함수 호출인 `obj?.method()` 형태로는 사용할 수 없다.

**23. Optional chaining(`?.`) 사용 시 주의사항으로 옳지 않은 것은?**
① 존재하지 않아도 괜찮은(선택적인) 대상에만 사용해야 하며, 남용하지 말아야 한다.
② 논리상 반드시 존재해야 하는 루트 객체(`userData`)까지 `userData?.address?.street`처럼 쓰면, 할당 누락 에러를 조기에 발견하기 어려워진다.
③ `?.` 맨 앞의 변수가 아예 선언조차 되어 있지 않아도 에러 없이 `undefined`를 반환한다.
④ `null`과 `undefined`일 때만 단락 평가가 동작한다.

**24. 다음 중 에러(`TypeError` 또는 `ReferenceError`)가 발생하는 코드는? (단, `userData`는 `{ name: 'Alice' }`로 선언되어 있고, `undeclaredVar`는 선언되지 않음)**
① `console.log(userData.address?.street)`
② `console.log(userData.nonMethod?.())`
③ `console.log(userData.address && userData.address.street)`
④ `console.log(undeclaredVar?.address)`

## [파트 4] 배열 기초 및 콜백 함수 (25~31번)

**25. 객체(Object)와 비교했을 때 배열(Array)이 가지는 특징으로 틀린 것은?**
① 순서가 중요한 데이터 묶음을 관리할 때 사용한다.
② 배열의 인덱스는 숫자로만 이루어져 있어, 키 자체가 데이터의 의미를 설명해주지 못한다.
③ 특정 값을 찾기 위해서는 배열의 모든 요소를 처음부터 순서대로 확인해야 하는 단점이 있다.
④ 배열 내부에 저장되는 요소들은 모두 동일한 자료형이어야만 한다.

**26. 배열의 기본 조작 메서드(`push`, `pop`, `unshift`, `shift`)에 대한 설명으로 옳은 것은?**
① 네 가지 메서드 모두 원본 배열을 수정하지 않고 새로운 배열을 반환한다.
② `push()`와 `unshift()`는 요소가 추가된 후의 '새로운 배열의 길이'를 반환한다.
③ `pop()`은 배열의 맨 앞 요소를 제거하고 그 요소를 반환한다.
④ `shift()`는 배열의 맨 끝 요소를 제거하고 그 요소를 반환한다.

**27. 배열이 클수록 모든 요소를 밀거나 당겨와야 해서 성능이 저하되므로 가급적 사용을 피해야 하는 메서드 조합은?**
① `push()`, `pop()`
② `unshift()`, `shift()`
③ `map()`, `filter()`
④ `forEach()`, `reduce()`

**28. 다음 코드의 실행이 끝난 후 `names` 배열의 상태와 `result` 변수에 저장된 값은?**
```js
const names = ['Alice', 'Bella']
names.push('Cathy')
const result = names.shift()
```
① `names`: `['Bella', 'Cathy']`, `result`: `'Alice'`
② `names`: `['Alice', 'Bella']`, `result`: `'Cathy'`
③ `names`: `['Bella', 'Cathy']`, `result`: `2`
④ `names`: `['Alice', 'Bella', 'Cathy']`, `result`: `'Alice'`

**29. 콜백 함수(Callback function)의 개념과 비유(진동벨)에 대한 설명으로 가장 거리가 먼 것은?**
① 다른 함수의 인자로 전달되어 특정 시점에 호출되는 함수이다.
② 함수의 실행 권한을 다른 함수에게 위임하는 것이다.
③ 카페에서 커피를 주문하고 진동벨(콜백 함수)을 받아두면, 커피 완성 시점(이벤트 발생)에 벨이 울리는(함수 실행) 것과 같다.
④ 콜백 함수는 오직 배열 메서드(`forEach`, `map` 등)에서만 사용할 수 있는 전용 문법이다.

**30. 콜백 함수를 사용하는 이유로 적절하지 않은 것은?**
① 뼈대 함수는 그대로 두고 부품 함수(콜백)만 교체하여 다양한 기능을 유연하게 구현할 수 있다.
② `setTimeout`처럼 시간이 걸리는 비동기 작업이 끝난 직후에 실행할 시점을 제어할 수 있다.
③ 배열의 요소를 순회하며 반복적인 작업을 깔끔하게 지시할 수 있다.
④ 콜백 함수를 사용하면 코드의 실행 속도가 동기 방식보다 항상 빨라진다.

**31. 다음 코드의 출력 순서로 올바른 것은?**
```js
console.log('A')
setTimeout(function () {
  console.log('B')
}, 0)
console.log('C')
```
> *(힌트: `setTimeout`의 타이머 콜백 동작 원리 참고)*
① `A` → `B` → `C`
② `A` → `C` → `B`
③ `B` → `A` → `C`
④ `C` → `B` → `A`

## [파트 5] Array Helper Methods: `forEach`, `map`, `filter` (32~41번)

**32. `forEach`, `map`, `filter` 메서드의 콜백 함수가 공통적으로 전달받는 매개변수 3개의 순서로 올바른 것은?**

**41. 기타 유용한 Array Helper Methods인 `find`, `some`, `every`에 대한 설명으로 틀린 것은?**

## [파트 6] 배열 전개 구문 및 심화/참고 (42~50번)

**42. 배열에서의 전개 구문(`...`)에 대한 설명으로 틀린 것은?**
① 배열의 대괄호를 없애고 내용물만 꺼내어 배열을 합치거나 중간에 삽입할 때 유용하다.
② 전개 구문은 항상 새로운 배열을 만들며 원본 배열은 변경되지 않는다.
③ 배열 안에 객체가 들어있는 경우, 전개 구문을 쓰면 내부 객체까지 완벽하게 깊은 복사(Deep Copy)가 이루어진다.
④ `['머리', ...['어깨', '무릎'], '발']`의 결과는 `['머리', '어깨', '무릎', '발']`이다.

**43. (심화) `reduce` 메서드의 구조와 동작 원리에 대한 설명으로 옳지 않은 것은?**
```js
arr.reduce((acc, cur, index, array) => {
  return nextAccValue
}, initialValue)
```
① 배열의 요소를 하나씩 줄여가며 숫자, 문자열, 객체, 배열 등 하나의 결과값으로 합칠 때 사용한다.
② `acc`(Accumulator)는 이전 단계까지 계산된 누적값이며, 콜백이 `return`한 값이 다음 단계의 `acc`가 된다.
③ `cur`(Current)는 현재 처리 중인 배열의 요소이다.
④ `initialValue`(초기값)는 숫자 `0`만 설정할 수 있으며, 빈 객체(`{}`)나 빈 배열(`[]`)은 사용할 수 없다.

**44. 다음 `reduce`를 활용한 코드의 실행 결과로 올바른 것은?**
```js
const names = ['Alice', 'Bob', 'Alice']
const counts = names.reduce((acc, name) => {
  acc[name] = (acc[name] || 0) + 1
  return acc
}, {})
console.log(counts)
```
① `['Alice', 'Bob', 'Alice']`
② `{ Alice: 2, Bob: 1 }`
③ `{ Alice: 1, Bob: 1 }`
④ `3`

**45. 모던 웹 개발(Vue, React 등)에서 `for...of`보다 `forEach`, `map` 같은 배열 메서드를 더 선호하는 이유로 가장 적절한 것은?**
① "어떻게(How) 순회할지" 제어하는 명령형 방식보다, "무엇을(What) 할지" 데이터 처리에 집중하는 선언형 프로그래밍 스타일을 지향하기 때문이다.
② `for...of` 문은 최신 브라우저에서 지원이 중단되었기 때문이다.
③ `forEach`가 `for...of`보다 무조건 메모리 사용량이 절반 이하이기 때문이다.
④ Vue와 Axios에서는 `for...of`를 사용하면 문법 에러가 발생하기 때문이다.

**46. "배열은 객체다"라는 명제에 대한 설명으로 틀린 것은?**
① 배열도 키와 속성들을 담고 있는 참조 타입(Reference Type)의 객체이다.
② 배열의 요소를 대괄호 표기법(`arr[0]`)으로 접근하는 원리는 객체의 대괄호 접근법과 같다.
③ 배열은 인덱스(숫자형 키)를 키로 가지며, `length` 속성을 갖는 특수한 객체이다.
④ 배열의 `length` 속성은 열거 가능(`enumerable: true`)하여 `Object.keys()`로 조회할 때 항상 마지막에 포함된다.

**47. JavaScript의 클래스(Class) 기본 문법에 대한 설명으로 틀린 것은?**

**49. 클래스로부터 새로운 인스턴스를 생성할 때 사용하는 `new` 연산자에 대한 설명으로 틀린 것은?**

### [파트 2] 메서드와 `this` 키워드
7. **②**
   - **해설**: 메서드는 객체 속성에 정의된 함수이며, `this`를 통해 자신이 속한 객체의 다른 속성에 접근할 수 있습니다.
8. **③**
   - **해설**: JavaScript에서 `this`는 함수가 선언될 때가 아니라 **호출되는 방식**에 따라 결정됩니다.
9. **③**
   - **해설**: 일반 함수를 단순 호출(`myFunc()`)하면 `this`는 전역 객체(`window`)를 가리킵니다.
10. **③**
    - **해설**: `myObj2.myFunc()` 내부의 `this`는 `myObj2`이지만, `forEach`의 인자로 전달된 일반 함수는 단순 호출되므로 그 내부의 `this`는 전역 객체(`window`)를 가리킵니다.
11. **②**
    - **해설**: 화살표 함수는 자신만의 `this`를 가지지 않고 외부 함수(`myFunc`)의 `this`(`myObj2`)를 그대로 가져오므로, `forEach`의 콜백을 화살표 함수로 작성하면 해결됩니다.
12. **①**
    - **해설**: 화살표 함수는 렉시컬(Lexical) `this`를 따르며, 상위 스코프의 `this`를 그대로 참조합니다.
13. **③**
    - **해설**: `this`의 동적 바인딩 덕분에 메서드를 하나만 정의해도 여러 객체가 이를 공유하며 각자의 데이터로 동작할 수 있습니다. (단, 유연함이 실수로 이어질 수 있다는 단점도 존재합니다.)

### [파트 3] JSON과 추가 객체 문법
14. **③**
    - **해설**: JSON은 특정 프로그래밍 언어에 종속되지 않는 독립적인 데이터 형식으로, API 통신 등에서 다양한 언어 간 데이터 교환에 널리 사용됩니다.
15. **②**
    - **해설**: Object → JSON 변환은 `JSON.stringify()`, JSON → Object 변환은 `JSON.parse()`를 사용합니다.
16. **②**
    - **해설**: 키와 변수명이 같을 때 축약하는 **단축 속성**(`name`)과, `function` 키워드를 생략하는 **단축 메서드**(`greeting()`)가 사용되었습니다.
17. **②**
    - **해설**: 대괄호(`[]`)로 둘러싸여 변수 값이나 연산 결과를 동적으로 키로 사용하는 문법을 **계산된 속성(computed property name)** 이라고 합니다.
18. **③**
    - **해설**: 객체 구조 분해 할당은 객체의 키 이름과 매칭하여 변수로 추출하며, 함수의 매개변수 자리(`function printInfo({ firstName, email })`)에서도 활용할 수 있습니다. 원본 객체는 수정되지 않습니다.
19. **②**
    - **해설**: 전개 구문(`...obj`) 이후에 동일한 키(`a: 1`)를 뒤에 작성하면 뒤에 쓴 값이 앞의 값(`a: 2`)을 덮어씁니다. 따라서 `{ a: 1, c: 3, d: 4, e: 5 }`가 됩니다.
20. **②**
    - **해설**: 얕은 복사는 겉(최상위 속성)만 새로 복사하고, 속(중첩된 내부 객체)은 메모리 주소값을 공유하는 복사 방식입니다.
21. **③**
    - **해설**: `Object.keys()`는 키 배열, `Object.values()`는 값 배열, `Object.entries()`는 `[key, value]` 쌍을 묶은 2차원 배열(`[['name', 'Alice'], ['age', 30]]`)을 반환합니다.
22. **④**
    - **해설**: Optional chaining은 `obj?.prop`, `obj?.[prop]`뿐만 아니라 존재하지 않을 수 있는 메서드를 호출할 때 `obj?.method()` 형태로도 사용할 수 있습니다.
23. **③**
    - **해설**: Optional chaining 맨 앞의 변수(`myObj?.address`에서 `myObj`)는 반드시 선언되어 있어야 합니다. 선언되지 않은 변수에 사용하면 `Uncaught ReferenceError`가 발생합니다.
24. **④**
    - **해설**: 선언되지 않은 변수 `undeclaredVar`에 `?.`를 사용하면 `ReferenceError: undeclaredVar is not defined` 에러가 발생합니다.

### [파트 4] 배열 기초 및 콜백 함수
25. **④**
    - **해설**: JavaScript 배열 요소의 자료형에는 제약이 없으며, 숫자, 문자열, 객체, 함수 등을 한 배열에 섞어서 담을 수 있습니다.
26. **②**
    - **해설**: 네 메서드 모두 원본 배열을 직접 수정합니다. `push()`와 `unshift()`는 추가 후의 새 배열 길이를 반환하고, `pop()`(끝 제거)과 `shift()`(앞 제거)는 제거한 요소를 반환합니다.
27. **②**
    - **해설**: 배열의 맨 앞을 조작하는 `unshift()`와 `shift()`는 나머지 모든 요소의 인덱스를 이동시켜야 하므로 배열이 클수록 성능이 저하됩니다.
28. **①**
    - **해설**: `push('Cathy')` 후 배열은 `['Alice', 'Bella', 'Cathy']`가 되고, `shift()`를 호출하면 맨 앞의 `'Alice'`가 제거되어 `result`에 담기며, `names`에는 `['Bella', 'Cathy']`가 남습니다.
29. **④**
    - **해설**: 콜백 함수는 배열 메서드뿐만 아니라 일반 함수, 이벤트 리스너, 타이머(`setTimeout`) 등 JavaScript 전반에서 광범위하게 사용됩니다.
30. **④**
    - **해설**: 콜백 함수는 기능의 유연성, 비동기 시점 제어, 배열 순회 등을 위해 사용하며, 단순 연산 속도를 높여주는 문법은 아닙니다.
31. **②**
    - **해설**: `setTimeout`에 전달된 콜백 함수는 비동기적으로 처리되어 현재 실행 중인 동기 코드(`A`, `C`)가 모두 끝난 뒤에 실행되므로 `A` → `C` → `B` 순으로 출력됩니다.

### [파트 5] Array Helper Methods: `forEach`, `map`, `filter`
32. **②**
    - **해설**: 세 메서드의 콜백 함수는 공통적으로 `(item, index, array)` 순서로 인자를 전달받습니다.
33. **③**
    - **해설**: `forEach`는 배열의 끝까지 무조건 진행하며, 중간에 `break`나 `continue`를 사용할 수 없습니다.
34. **③**
    - **해설**: 반복 도중 멈추거나 건너뛰는 제어(`break`, `continue`)가 필요할 때는 `for...of` 반복문이나 기본 `for` 문을 사용해야 합니다.
35. **④**
    - **해설**: `map`은 불변성(Immutability)을 유지하며 **원본 배열을 절대 변경하지 않고** 항상 새로운 배열을 반환합니다.
36. **③**
    - **해설**: `forEach`는 항상 `undefined`를 반환하므로 `result1`은 `undefined`입니다. `result2`의 `map` 콜백에서는 중괄호(`{}`)를 사용했음에도 `return` 키워드를 적지 않았기 때문에 각 요소마다 `undefined`가 반환되어 `[undefined, undefined, undefined]`가 됩니다.
37. **②**
    - **해설**: Python은 `list(map(함수, 리스트))`처럼 형변환이 필요하지만, JavaScript는 `배열.map(함수)` 형태로 즉시 새 배열을 반환합니다.
38. **①**
    - **해설**: `filter`는 콜백의 반환값이 `true`(truthy)인 요소만 모아 새 배열을 반환합니다. 조건에 맞는 요소가 하나도 없으면 빈 배열 `[]`을 반환하며, 길이는 원본보다 같거나 작습니다.
39. **②**
    - **해설**: 원본 데이터를 파괴하지 않고 삭제하려는 ID를 제외한 나머지 요소만 남기는 `products.filter(product => product.id !== 3)` 방식을 주로 사용합니다.
40. **①**
    - **해설**: `filter`를 통해 홀수인 `[1, 3, 5]`가 선별되고, 이어서 `map` 체이닝을 통해 각 요소에 10을 곱한 `[10, 30, 50]`이 반환됩니다.
41. **④**
    - **해설**: `some`과 `every`는 불리언 값(`true` 또는 `false`)을 반환하는 메서드이며, 새로운 배열을 반환하지 않습니다.

### [파트 6] 배열 전개 구문 및 심화/참고
42. **③**
    - **해설**: 배열 전개 구문 역시 **얕은 복사**를 수행하므로, 배열 내부에 들어있는 객체는 데이터가 아닌 주소값만 복사됩니다. 따라서 복사본 배열 내의 객체 속성을 수정하면 원본도 바뀝니다.
43. **④**
    - **해설**: `reduce`의 초기값(`initialValue`)에는 숫자뿐만 아니라 빈 객체(`{}`), 빈 배열(`[]`), 문자열 등 어떤 자료형도 설정할 수 있습니다.
44. **②**
    - **해설**: 초기값 `{}`에서 시작하여 각 이름의 등장 횟수를 누적하므로 `{ Alice: 2, Bob: 1 }` 객체가 반환됩니다.
45. **①**
    - **해설**: `forEach`, `map` 등은 "무엇을(What) 할지"에 집중하는 **선언형 프로그래밍** 스타일로 데이터의 흐름이 명확해지며, Vue나 Axios(`then` 콜백) 등 프레임워크 생태계의 기본 구조와 맞닿아 있기 때문입니다.
46. **④**
    - **해설**: `Object.getOwnPropertyDescriptors()`로 확인해보면 배열의 `length` 속성은 `enumerable: false`(열거 불가)로 설정되어 있어 `Object.keys()`나 `for...in` 등에서 열거되지 않습니다.
47. **③**
    - **해설**: 클래스 내부에는 `constructor`라는 이름을 가진 생성자 메서드가 **단 하나만** 존재할 수 있습니다.
48. **①**
    - **해설**: 클래스는 ES6에서 도입되었으며 내부적으로 생성자 함수를 기반으로 동작합니다. 익명 클래스 표현식도 가능하며, 내부 메서드는 `function` 키워드 없이 작성합니다.
49. **③**
    - **해설**: `new` 연산자 없이 클래스를 호출하면 `Uncaught TypeError`가 발생합니다.
50. **②**
    - **해설**: 한 사람의 속성들을 묶을 때는 **객체**, 여러 사람을 목록으로 관리할 때는 **배열**, 목록 전체에 동일한 작업을 시킬 때는 **배열 헬퍼 메서드**를 사용합니다.
