## 문제 (총 10문항, 각 10점)

### 1. 웹 페이지에서의 이벤트 처리 과정 (카페 키오스크 비유) [10점]
강의 자료에서는 웹 페이지의 이벤트 처리 과정을 **'카페에서 손님이 키오스크로 주문하고 바리스타가 커피를 만드는 과정'**에 비유하고 있습니다. 
`이벤트(event)`, `이벤트 리스너(event listener)`, `이벤트 핸들러(event handler)` 세 가지 개념의 정의와 역할을 이 비유(손님의 주문, 키오스크, 바리스타)와 연결하여 서술하시오.

---

### 2. `.addEventListener()`에 핸들러 등록 시 함수 괄호 생략 이유 [10점]
`button.addEventListener('click', handleClick)`과 같이 이벤트 핸들러를 등록할 때, `handleClick()`처럼 함수 이름 뒤에 소괄호 `()`를 붙이지 않고 `handleClick`으로 전달해야 하는 이유를 **콜백 함수의 호출 주체 및 실행 시점** 관점에서 서술하시오.

---

### 3. 이벤트 객체(`event object`)의 생성과 역할 [10점]
DOM 요소에서 이벤트가 발생했을 때 생성되는 **이벤트 객체(`event object`)**는 누가 언제 생성하며, 어떤 정보를 담고 있고, 이벤트 핸들러 함수 내부에서는 이를 어떻게 전달받아 활용할 수 있는지 서술하시오.

---

### 4. 이벤트 버블링(Bubbling)과 캡처링(Capturing)의 비교 [10점]
표준 DOM 이벤트 흐름에서 **캡처링(Capturing)**과 **버블링(Bubbling)**의 개념을 각각 설명하고, 중첩된 요소(`form > div > p`)에서 가장 안쪽의 `<p>` 요소를 클릭했을 때 두 단계의 **이벤트 전파 방향(순서)**이 어떻게 다른지 비교하여 서술하시오.

---

### 5. `event.target`과 `event.currentTarget`의 차이점 [10점]
최상위 요소인 `#outerouter`에만 클릭 이벤트 핸들러가 등록되어 있고, 그 안에 `#outer > #inner`가 중첩되어 있는 구조가 있습니다. 사용자가 가장 안쪽의 **`#inner` 요소를 클릭했을 때** `#outerouter`의 핸들러가 실행되는 이유를 밝히고, 이때 핸들러 내부에서 `event.target`과 `event.currentTarget`이 각각 어떤 요소를 가리키는지 차이점을 서술하시오.

### 6. 이벤트 버블링의 필요성과 활용 (이벤트 위임 패턴) [10점]
하나의 부모 `<div>` 요소 안에 각기 다른 동작을 하는 100개의 `<button>` 자식 요소가 있습니다. 각 버튼마다 개별적으로 이벤트 핸들러를 등록하지 않고 **효율적으로 이벤트를 처리하는 방법**이 무엇인지 설명하고, 그 방법이 동작하는 원리를 서술하시오.

### 7. 콘솔에서 `event` 객체 확인 시 `currentTarget`이 `null`이 되는 이유와 대처법 [10점]
이벤트 핸들러 내부에서 `console.log(event)`를 실행한 뒤, 브라우저 개발자 도구 콘솔에서 출력된 이벤트 객체를 펼쳐 보면 `currentTarget` 속성의 값이 `null`로 표시됩니다. 이러한 현상이 발생하는 **원인**과, 이를 해결하여 요소의 정보를 정상적으로 확인할 수 있는 **대처 방법 2가지**를 서술하시오.

`event.preventDefault()` 메서드의 역할이 무엇인지 강의 자료의 **'택배 기사님 비유'** 또는 개념 정의를 바탕으로 설명하고, 실제 웹 개발에서 이 메서드가 사용되는 **구체적인 활용 예시를 2가지 이상** 들어 서술하시오.

`addEventListener`의 이벤트 핸들러로 **일반 함수(`function () {}`)**를 사용했을 때와 **화살표 함수(`() => {}`)**를 사용했을 때 함수 내부의 `this`가 가리키는 대상이 어떻게 달라지는지 그 **원인**과 함께 설명하고, 화살표 함수를 사용하면서도 이벤트 리스너가 연결된 요소에 접근할 수 있는 **해결책**을 서술하시오.

### 1. 웹 페이지에서의 이벤트 처리 과정 (카페 키오스크 비유) [10점]
* **모범 답안:**
  웹 페이지에서 사용자의 클릭이나 입력 등 '무언가 일어났다는 신호 또는 사건'을 **이벤트(event)**라고 하며, 이는 카페에서 손님이 하는 **'주문'**에 해당합니다. 특정 요소에서 이벤트가 발생하는지 감지하고 주문을 받는 역할은 **이벤트 리스너(event listener, `addEventListener`)**이며 카페의 **'키오스크'**에 해당합니다. 마지막으로 이벤트가 발생했을 때 실행되는 콜백 함수는 **이벤트 핸들러(event handler)**라고 하며, 주문에 맞춰 커피를 제조하는 **'바리스타의 행동'**에 해당합니다.
* **키워드 채점 기준:**
  * **[3점]** **이벤트(Event)** = 웹 페이지에서 일어나는 신호/사건 = **손님의 주문**(클릭, 입력 등) 연결 설명
  * **[3점]** **이벤트 리스너(Event Listener)** = 이벤트를 감지/수신하여 핸들러를 연결하는 장치 = **키오스크** 연결 설명
  * **[4점]** **이벤트 핸들러(Event Handler)** = 이벤트 발생 시 실행되는 (콜백)함수 = **바리스타의 행동**(커피 제조) 연결 설명

### 2. `.addEventListener()`에 핸들러 등록 시 함수 괄호 생략 이유 [10점]
* **모범 답안:**
  이벤트 핸들러는 개발자가 코드에서 직접 호출하는 함수가 아니라, 지정한 이벤트가 발생했을 때 **브라우저가 대신 호출해 주는 콜백(callback) 함수**입니다. `addEventListener`로 핸들러를 등록할 때는 함수를 지금 당장 실행하겠다는 것이 아니라 '이벤트가 발생하면 어떤 함수를 실행할지(함수의 참조)'를 알려주는 과정입니다. 만약 `handleClick()`처럼 괄호를 붙이면 이벤트가 발생하기를 기다리지 않고 **등록하는 시점에 함수가 즉시 실행**되어 버리므로 괄호 없이 함수 이름만 전달해야 합니다.
* **키워드 채점 기준:**
  * **[3점]** 핸들러는 개발자가 직접 호출하지 않고 이벤트 발생 시 **브라우저가 호출하는 콜백 함수**라는 점 언급
  * **[4점]** 괄호 `()`를 붙이면 이벤트 발생 시점이 아니라 **코드 등록 시점에 함수가 즉시 호출(실행)**된다는 문제점 언급
  * **[3점]** 따라서 '누구를 부를지' **함수 자체(참조)를 전달**하기 위해 괄호를 생략한다는 논리 포함

---

### 3. 이벤트 객체(`event object`)의 생성과 역할 [10점]
* **모범 답안:**
  DOM 요소에서 이벤트가 발생하면 **브라우저**가 그 순간 해당 이벤트에 관한 상세 정보를 담은 **이벤트 객체(`event object`)를 자동으로 생성**합니다. 이 객체 안에는 이벤트 유형(`type`), 이벤트가 발생한 요소(`target`, `currentTarget`), 마우스 좌표, 눌린 키보드 키 등의 상세 정보가 담겨 있습니다. 생성된 이벤트 객체는 이벤트 핸들러 함수의 **첫 번째 매개변수(인자)로 자동 전달**되므로, 핸들러 정의 시 `function (event) {}`와 같이 매개변수를 선언하여 내부에서 참조하고 활용할 수 있습니다.
* **키워드 채점 기준:**
  * **[3점]** 이벤트 발생 시 **브라우저가 자동으로 생성**한다는 점 언급
  * **[3점]** 이벤트 발생 순간의 **상세 정보**(발생 요소, 이벤트 타입, 마우스 좌표, 눌린 키 등)를 담고 있다는 점 언급
  * **[4점]** 이벤트 핸들러 함수의 **첫 번째 매개변수(인자)로 자동 전달**되어 사용할 수 있다는 점 언급

---

### 4. 이벤트 버블링(Bubbling)과 캡처링(Capturing)의 비교 [10점]
* **모범 답안:**
  **캡처링(Capturing)**은 이벤트가 발생했을 때 최상위 조상(`window`, `document`)에서 시작하여 실제 이벤트가 발생한 타겟 요소까지 **하위로(위에서 아래로) 전파**되는 단계입니다. 반면 **버블링(Bubbling)**은 이벤트가 발생한 가장 안쪽의 타겟 요소에서 핸들러가 동작한 후, 부모 요소를 거슬러 올라가며 최상단 조상 요소를 만날 때까지 **상위로(아래에서 위로) 전파**되는 현상입니다. 따라서 `<p>` 요소를 클릭하면 캡처링 단계에서는 `form → div → p` 순서로 하향 전파되고, 버블링 단계에서는 `p → div → form` 순서로 상향 전파되며 각 핸들러가 실행됩니다.
* **키워드 채점 기준:**
  * **[3점]** **캡처링**: 최상위 조상에서 타겟 요소로 내려가는 **하향 전파**(`form → div → p`) 설명
  * **[4점]** **버블링**: 타겟 요소에서 시작해 부모 및 최상단 조상(`document`, `window`)으로 거슬러 올라가는 **상향 전파**(`p → div → form`) 설명
  * **[3점]** 두 단계의 전파 방향이 **서로 반대**(캡처링 후 타겟을 거쳐 버블링 진행)라는 비교 설명 포함

---

### 5. `event.target`과 `event.currentTarget`의 차이점 [10점]
* **모범 답안:**
  `#inner`에는 핸들러가 없지만 `#inner`를 클릭하면 **이벤트 버블링**에 의해 부모인 `#outer`를 거쳐 `#outerouter`까지 클릭 이벤트가 전파되기 때문에 `#outerouter`의 핸들러가 실행됩니다. 이때 **`event.target`**은 실제 이벤트가 최초로 시작된 가장 안쪽의 요소를 참조하며 버블링이 진행되어도 변하지 않으므로 **`#inner`**를 가리킵니다. 반면 **`event.currentTarget`**은 현재 실행 중인 이벤트 핸들러(리스너)가 연결된 요소만을 참조하며 일반 함수의 `this`와 같으므로 **`#outerouter`**를 가리킵니다.
* **키워드 채점 기준:**
  * **[2점]** 하위 요소 클릭 시 상위 핸들러가 동작하는 이유로 **이벤트 버블링(전파)** 언급
  * **[4점]** **`event.target`**: 실제 **이벤트가 최초로 발생한(시작된) 가장 안쪽 요소**를 참조하며 `#inner`를 가리킴 (버블링되어도 불변)
  * **[4점]** **`event.currentTarget`**: **이벤트 핸들러(리스너)가 연결된 현재 요소**(`this`와 동일)를 참조하며 `#outerouter`를 가리킴

---

### 6. 이벤트 버블링의 필요성과 활용 (이벤트 위임 패턴) [10점]
* **모범 답안:**
  100개의 버튼에 각각 핸들러를 등록하는 대신, 버튼들의 **공통 조상(상위 요소)인 `<div>` 요소에 이벤트 핸들러를 단 하나만 등록**하여 처리합니다(이벤트 위임). 자식 `<button>`에서 클릭 이벤트가 발생하면 **이벤트 버블링**에 의해 부모인 `<div>`까지 이벤트가 전파되어 `<div>`의 핸들러가 실행됩니다. 이때 핸들러 내부에서 **`event.target`** 속성을 확인하면 100개의 버튼 중 실제로 어떤 자식 버튼이 클릭되었는지 정확히 알 수 있으므로 한곳에서 효율적으로 이벤트를 다룰 수 있습니다.
* **키워드 채점 기준:**
  * **[4점]** 개별 버튼이 아닌 **공통 조상(상위/부모 `<div>` 요소)에 이벤트 핸들러를 하나만 등록**한다는 해결 방법 제시
  * **[3점]** 자식 요소의 이벤트가 부모로 전달되는 원리로 **이벤트 버블링** 언급
  * **[3점]** 부모 핸들러 내부에서 실제 클릭된 버튼을 식별하는 방법으로 **`event.target`** 활용 언급

### 7. 콘솔에서 `event` 객체 확인 시 `currentTarget`이 `null`이 되는 이유와 대처법 [10점]
* **모범 답안:**
  `event.currentTarget`은 **이벤트가 처리되는(이벤트 핸들러가 실행되는) 동안에만 값이 존재하는 속성**이기 때문입니다. `console.log(event)`로 객체 전체를 출력해 놓고 나중에 개발자 도구에서 화살표를 눌러 펼쳐볼 때는 이미 이벤트 전파와 처리가 모두 끝난 시점이므로 `currentTarget`이 `null`로 초기화된 상태가 보입니다. 이를 해결하려면 ① 핸들러 실행 중에 **`console.log(event.currentTarget)`으로 직접 해당 속성을 출력**하거나, ② 이벤트 처리가 끝난 후에도 값이 변하지 않고 유지되는 **`event.target` 속성을 참고**하여 하위 속성 값들을 확인해야 합니다.
* **키워드 채점 기준:**
  * **[4점]** **원인**: `currentTarget`은 **이벤트가 처리되는(진행 중인) 동안에만 사용할 수 있는 속성**이라 처리 후에는 `null`이 된다는 점 설명
  * **[3점]** **대처법 1**: 핸들러 내부에서 **`console.log(event.currentTarget)`**을 직접 호출하여 실행 순간의 값을 출력
  * **[3점]** **대처법 2**: 이벤트 종료 후에도 유지되는 **`event.target`** 속성을 참고하여 하위 속성 값 확인

### 9. `event.preventDefault()`의 역할과 실제 활용 사례 [10점]
* **모범 답안:**
  `event.preventDefault()`는 HTML 요소가 **기본적으로 가지고 있는 이벤트 동작을 실행하지 않도록 취소**하는 메서드입니다(택배 기사님의 기본 동작인 '문 앞에 두기'를 취소하고 내가 정한 로직인 '경비실에 맡기기'로 처리하는 것과 같습니다). 대표적인 활용 사례로는 ① **`<form>` 요소가 제출(`submit`)될 때 페이지가 새로고침되는 기본 동작을 막는 경우**, ② **콘텐츠 복사(`copy` 이벤트) 시 텍스트가 클립보드에 복사되는 것을 방지하는 경우**, ③ **`<a>` 태그 클릭 시 기본 링크 주소로 페이지가 이동하는 것을 막고 다른 로직을 수행하는 경우** 등이 있습니다.
* **키워드 채점 기준:**
  * **[4점]** HTML 요소의 **기본 동작을 취소(방지)**하고 개발자가 원하는 로직을 수행하게 한다는 핵심 역할(또는 택배 비유) 설명
  * **[3점]** **사례 1**: `<form>` 태그의 **`submit` 이벤트 시 페이지 새로고침 방지** 언급
  * **[3점]** **사례 2**: 텍스트 **`copy`(복사) 이벤트 방지** 또는 **`<a>` 태그 클릭 시 페이지 이동 방지** 중 1가지 이상 언급

### 10. `addEventListener`에서의 화살표 함수와 `this` 바인딩 주의사항 [10점]
* **모범 답안:**
  일반 함수를 이벤트 핸들러로 사용하면 함수 내부의 `this`는 **이벤트 리스너가 연결된 DOM 요소**(`event.currentTarget`)를 가리킵니다. 반면 **화살표 함수는 자신만의 `this`를 가지지 않고, 자신이 선언된 상위 스코프의 `this`를 그대로 물려받아 사용**하기 때문에 화살표 함수 핸들러 내부에서 `this`를 출력하면 대부분 **전역 객체(`window`)**를 가리키게 됩니다. 따라서 이벤트 연결 요소를 참조하려면 ① 화살표 함수 대신 **일반 함수**를 사용하거나, ② 화살표 함수를 유지할 경우 매개변수로 받은 이벤트 객체의 **`event.currentTarget`** 속성을 사용해야 합니다.
* **키워드 채점 기준:**
  * **[3점]** **일반 함수의 `this`**는 이벤트 리스너가 연결된 DOM 요소를 가리키는 반면, **화살표 함수의 `this`**는 **전역 객체(`window`)**를 가리킨다는 차이점 명시
  * **[4점]** **원인**: 화살표 함수는 **자신만의 `this`가 없고 상위 스코프의 `this`를 물려받기(상속하기) 때문**이라는 원리 설명
  * **[3점]** **해결책**: 일반 함수로 바꾸어 쓰거나, 화살표 함수 내에서 `this` 대신 **`event.currentTarget`**을 사용한다는 해결법 제시
