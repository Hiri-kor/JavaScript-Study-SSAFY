## 문제 (문항당 10점)

**1. [데이터 타입] JavaScript의 데이터 타입인 '원시 자료형(Primitive type)'과 '참조 자료형(Reference type)'의 차이점을 ① 저장 방식, ② 변경 가능성(불변/가변), ③ 변수 간 할당 시 복사되는 대상 및 원본에 미치는 영향을 기준으로 비교하여 서술하시오.**

**2. [null과 undefined] JavaScript에서 '값이 없음'을 나타내는 `null`과 `undefined`의 의미 차이를 설명하고, `typeof null`을 실행했을 때 `'object'`가 반환되는 역사적 배경(이유)을 서술하시오.**

**3. [비교 연산자] 동등 연산자(`==`)와 일치 연산자(`===`)의 동작 방식 차이를 설명하고, 실무에서 특별한 경우를 제외하고 일치 연산자(`===`)의 사용을 권장하는 이유를 `[1] == [1]` 또는 `'1' == 1`과 같은 예시와 함께 서술하시오.**

**4. [논리 연산자] 논리 연산자 `&&`(AND)와 `||`(OR)에서 지원하는 '단축 평가(Short-circuit evaluation)'의 개념을 설명하고, 아래 두 코드가 각각 어떤 과정을 거쳐 해당 값을 반환하는지 서술하시오.**
```js
console.log(0 && 1) // 0
console.log(4 || 7) // 4
```

**5. [반복문 비교] `for...in` 반복문과 `for...of` 반복문의 순회 대상과 반환 값의 차이를 설명하고, 일반 객체(`{ korea: '서울' }`)에 `for...of`를 사용했을 때 발생하는 현상과 그 이유를 서술하시오.**

**6. [배열과 반복문] 배열(`Array`)을 순회할 때 `for...in` 반복문을 사용하지 않고 일반 `for` 문이나 `for...of` 반복문을 사용할 것을 권장하는 이유를 3가지 측면에서 서술하시오.**

**7. [반복문과 변수 선언] 일반 `for` 문(`for (const i = 0; i < 5; i++)`)에서는 제어 변수 선언에 `const`를 사용하면 에러가 발생하지만, `for...in`이나 `for...of` 반복문(`for (const item of arr)`)에서는 `const`를 사용해도 에러가 발생하지 않는 이유를 비교하여 서술하시오.**

**8. [함수 정의와 호이스팅] '함수 선언식'과 '함수 표현식'의 정의 방식 및 선언 전 호출 가능 여부(호이스팅 및 TDZ 관점)의 차이를 설명하고, 개발 시 '함수 표현식' 사용을 더 권장하는 이유를 2가지 이상 서술하시오.**

**9. [매개변수와 전개 구문] 함수에서 점 세 개(`...`) 기호를 사용하는 '나머지 매개변수(Rest parameter)'와 함수 호출 시의 '전개 구문(Spread syntax)'의 역할 차이를 설명하고, 나머지 매개변수를 작성할 때 지켜야 할 문법적 규칙 2가지를 서술하시오.**

**10. [화살표 함수] 일반 함수 표현식을 '화살표 함수(Arrow function)'로 축약하는 3단계를 설명하고, 중괄호와 `return`을 생략한 화살표 함수에서 객체(`{ key: 'value' }`)를 반환할 때 주의해야 할 점과 해결 방법을 서술하시오.**

## 모범 답안 및 키워드 채점 기준

> **채점 안내**: 문장의 표현이 조금 다르더라도 아래 제시된 **핵심 키워드(또는 동일한 의미의 표현)**가 정확한 맥락으로 포함되어 있다면 배점을 부여합니다.

### 1번 채점 기준 (10점)
* **모범 답안**: 원시 자료형은 변수에 **값 자체**가 직접 저장되며 데이터가 **불변(immutable)**합니다. 따라서 다른 변수에 할당할 때 **값이 복사**되므로 한쪽을 수정해도 원본(다른 변수)에 **영향을 주지 않습니다**. 반면 참조 자료형은 데이터가 저장된 **메모리의 주소**가 변수에 저장되며 데이터가 **가변(mutable)**입니다. 변수 간 할당 시 **주소가 복사**되므로 복사본의 속성을 수정하면 원본의 값도 **함께 변경(영향을 미침)**됩니다.
* **키워드 배점**:
  * `[3점]` 저장 방식: 원시 자료형은 **값 자체** 저장, 참조 자료형은 **메모리 주소** 저장
  * `[3점]` 변경 가능성: 원시 자료형은 **불변(immutable)**, 참조 자료형은 **가변(mutable)**
  * `[4점]` 할당 및 영향: 원시 자료형은 **값 복사**(서로 **영향 없음**), 참조 자료형은 **주소 복사**(원본과 사본이 서로 **영향을 미침**)

### 2번 채점 기준 (10점)
* **모범 답안**: `null`은 개발자가 **의도적으로 '값이 없음'**을 나타낼 때 할당하는 값이고, `undefined`는 시스템이나 엔진이 변수가 선언된 후 **'값이 할당되지 않음'**을 나타낼 때 사용하는 값입니다. `typeof null`이 `'object'`를 반환하는 이유는 자바스크립트 초기 버전의 **버그(설계 오류)** 때문입니다. 초기 **32비트 시스템**에서 하위 3비트를 타입 태그로 사용했는데, 객체를 나타내는 태그가 **`000`**이었고 모든 비트가 0인 `null` 포인터 역시 하위 비트가 **`000`**이어서 객체로 잘못 판별하게 되었으며, 이후 **하위 호환성** 문제로 수정되지 못했습니다.
* **키워드 배점**:
  * `[2점]` `null`의 정의: 개발자(프로그래머)가 **의도적으로 값이 없음**을 표현
  * `[2점]` `undefined`의 정의: 시스템/엔진에 의해 **값이 할당되지 않음**을 표현
  * `[4점]` 역사적 기술 배경: 초기 버전의 **버그(오류)**로, **32비트 시스템**에서 객체의 타입 태그(**`000`**)와 모든 비트가 0인 `null`이 겹침
  * `[2점]` 유지 이유(선택/가산): 기존 웹 사이트와의 **하위 호환성** 때문에 수정하지 못함 (앞선 기술 배경을 완벽히 썼다면 만점 처리)

### 3번 채점 기준 (10점)
* **모범 답안**: 동등 연산자(`==`)는 비교 시 **암묵적 타입 변환**을 통해 두 피연산자의 타입을 일치시킨 후 같은 값인지 비교합니다. 반면 일치 연산자(`===`)는 암묵적 타입 변환 없이 **값과 타입이 모두 같은지** 엄격하게 비교합니다.(객체의 경우 둘 다 같은 메모리 주소를 가리키는지 판별) `'1' == 1`이나 `0 == false`가 `true`가 되는 것처럼 동등 연산자는 직관과 다른 **예측하지 못한 결과**를 만들어 버그를 유발할 수 있으므로, 엄격하고 예측 가능한 **일치 연산자(`===`)** 사용을 권장합니다.
* **키워드 배점**:
  * `[3점]` 동등 연산자(`==`): **암묵적 타입 변환**(자동 형 변환) 수행 후 값 비교
  * `[3점]` 일치 연산자(`===`): 타입 변환 없이 **값과 타입 모두** 같은지 엄격하게 비교
  * `[4점]` 권장 이유 및 예시: 암묵적 타입 변환으로 인한 **예측 불가능한 결과(오류/버그) 방지** 및 적절한 비교 예시 제시

### 4번 채점 기준 (10점)
* **모범 답안**: **단축 평가**란 논리 연산에서 앞(왼쪽) 피연산자의 평가 결과만으로 전체 결과가 확정될 경우, **뒤(오른쪽) 피연산자를 평가하지 않고** 평가를 결정지은 피연산자의 값을 그대로 반환하는 동작입니다. `0 && 1`에서는 AND 연산의 첫 피연산자인 `0`이 **거짓(falsy)**으로 평가되므로 뒤의 `1`을 보지 않고 즉시 **`0`을 반환**합니다. `4 || 7`에서는 OR 연산의 첫 피연산자인 `4`가 **참(truthy)**으로 평가되므로 뒤의 `7`을 평가하지 않고 즉시 **`4`를 반환**합니다.
* **키워드 배점**:
  * `[4점]` 단축 평가 정의: 좌항만으로 결과가 확정되면 **우항을 평가(실행)하지 않고** 해당 **원래 피연산자 값**을 반환함
  * `[3점]` `0 && 1` 설명: 좌항 `0`이 **거짓(false/falsy)**이므로 우항을 평가하지 않고 `0` 반환
  * `[3점]` `4 || 7` 설명: 좌항 `4`가 **참(true/truthy)**이므로 우항을 평가하지 않고 `4` 반환

### 5번 채점 기준 (10점)
* **모범 답안**: `for...in`은 객체의 열거 가능한(enumerable) 속성의 **키(key)**를 순회하며, `for...of`는 배열이나 문자열처럼 **반복 가능한(iterable) 객체**의 **값(value)**을 순회합니다. 일반 객체(`Object`)는 **반복 가능한(iterable) 객체가 아니기 때문에**, 일반 객체에 `for...of`를 사용하면 **`TypeError` (`... is not iterable`)** 에러가 발생합니다.
* **키워드 배점**:
  * `[3점]` `for...in` 특징: 객체의 열거 가능한 속성 **키(key)** 순회
  * `[3점]` `for...of` 특징: **반복 가능한(iterable)** 객체의 **값(value)** 순회
  * `[4점]` 일반 객체에 `for...of` 사용 시: 일반 객체는 **iterable(반복 가능)하지 않으므로** **`TypeError`(에러)**가 발생함

### 6번 채점 기준 (10점)
* **모범 답안**: 첫째, `for...in`은 배열의 요소 값이 아니라 인덱스를, 그것도 숫자가 아닌 **'문자열' 형태의 키**로 반환하기 때문입니다. 둘째, 내부적으로 배열의 반복자가 아닌 속성 열거를 사용하므로 **인덱스 순서를 보장할 수 없기** 때문입니다. 셋째, 정수가 아닌 이름의 속성이나 배열의 **프로토타입(prototype)에 추가된 속성까지 모두 순회**하여 예기치 않은 버그를 유발할 수 있기 때문입니다.
* **키워드 배점**:
  * `[4점]` 이유 1: 배열의 값(value)이 아닌 **인덱스(키)를 문자열**로 반환함
  * `[3점]` 이유 2: 특정 순서에 따라 인덱스를 반환하는 **순서를 보장하지 않음**
  * `[3점]` 이유 3: 정수가 아닌 속성이나 **프로토타입에 추가된 열거 가능한 속성**까지 모두 순회함

### 7번 채점 기준 (10점)
* **모범 답안**: 일반 `for` 문에서는 최초 정의한 제어 변수 `i`의 값을 매 반복마다 증감문(`i++`)을 통해 **재할당**하면서 사용하기 때문에, 재할당이 불가능한 상수 키워드 `const`를 사용하면 에러가 발생합니다. 반면 `for...in`이나 `for...of` 반복문은 기존 변수를 재할당하는 것이 아니라, **매 반복마다 새로운 변수(스코프 바인딩)에 다른 속성 이름이나 값이 지정**되는 방식이므로 블록 내부에서 직접 변수를 수정하지 않는 한 `const`를 사용해도 에러가 발생하지 않습니다.
* **키워드 배점**:
  * `[5점]` 일반 `for` 문 에러 이유: 최초 선언한 하나의 변수에 값을 계속 **재할당**(`i++`)하기 때문
  * `[5점]` `for...in` / `for...of` 가능 이유: 재할당이 아니라 **매 반복마다 새로운 변수에 값이 지정(바인딩)**되기 때문

### 8번 채점 기준 (10점)
* **모범 답안**: **함수 선언식**은 함수 전체가 **호이스팅(Hoisting)**되어 함수를 **선언하기 전에도 호출**할 수 있습니다. 반면 **함수 표현식**은 익명 함수를 변수에 할당하는 방식으로, 변수는 호이스팅되지만 실제 함수가 할당되는 줄에 도달하기 전까지 **TDZ(일시적 사각지대)**에 머물러 선언 전에 호출하면 **`ReferenceError`**가 발생합니다. 함수 표현식을 권장하는 이유는 ① '정의 후 호출' 순서가 강제되어 코드 실행 흐름의 **예측 가능성**이 높고, ② 함수를 변수에 할당하여 값으로 다루는 **유연성**이 좋으며, ③ `let`/`const`와 함께 사용하여 엄격한 **블록 스코프 관리**가 가능하기 때문입니다.
* **키워드 배점**:
  * `[3점]` 함수 선언식: 함수 전체가 **호이스팅**되어 **선언 전 호출 가능**
  * `[3점]` 함수 표현식: 변수에 함수를 할당하며, **TDZ**로 인해 **선언 전 호출 불가능 (`ReferenceError`)**
  * `[4점]` 표현식 권장 이유 (아래 3가지 중 2가지 이상 포함 시 만점, 1가지만 포함 시 2점):
    1. **예측 가능성** (정의 후 호출 순서가 드러남)
    2. **유연성** (변수에 할당되어 함수를 값으로 다루기 쉬움)
    3. **스코프 관리** (`let`, `const`의 블록 스코프 활용)

### 9번 채점 기준 (10점)
* **모범 답안**: **나머지 매개변수**는 함수 정의 시 정해지지 않은 개수의 인자들을 하나의 **배열로 압축(모아서)** 받는 역할을 하고, 함수 호출 시 사용하는 **전개 구문**은 배열 등 반복 가능한(iterable) 객체를 **개별 인자로 펼쳐서(확장하여)** 전달하는 역할을 합니다. 나머지 매개변수의 작성 규칙은 첫째, 함수 정의에서 **단 하나만** 작성할 수 있으며, 둘째, 반드시 매개변수 목록의 **맨 마지막에 위치**해야 합니다.
* **키워드 배점**:
  * `[3점]` 나머지 매개변수 역할: 여러 인자들을 하나의 **배열로 모아서(압축하여)** 받음
  * `[3점]` 전개 구문 역할: 반복 가능한 객체를 **개별 요소(인자)로 펼쳐서(확장하여)** 전달함

### 10번 채점 기준 (10점)
* **모범 답안**: 화살표 함수 작성 과정은 ① `function` 키워드를 제거하고 매개변수와 중괄호 사이에 **화살표(`=>`)**를 작성합니다. ② 매개변수가 **1개뿐이라면 소괄호 `()`를 생략**할 수 있습니다. ③ 함수 본문이 표현식 **한 줄이라면 중괄호 `{}`와 `return`을 함께 생략**할 수 있습니다. 단, `return`을 생략하고 객체를 반환할 때 `{ key: 'value' }`처럼 작성하면 자바스크립트 엔진이 객체의 중괄호를 **함수 본문의 블록 중괄호로 해석**하여 `undefined`가 반환됩니다. 따라서 객체를 **`({ key: 'value' })`와 같이 소괄호 `()`로 감싸야** 정상적으로 객체가 반환됩니다.
* **키워드 배점**:
  * `[5점]` 축약 3단계: ① `function` 제거 및 **`=>` 추가**, ② 인자 1개일 때 **`()` 생략**, ③ 본문 1줄일 때 **`{}`와 `return` 동시 생략** (단계별 1.5~2점)
  * `[2점]` 객체 반환 시 주의점: 객체의 중괄호 `{}`가 **함수 본문(블록)으로 인식**되어 값이 반환되지 않음
  * `[3점]` 해결 방법: 반환할 객체를 **소괄호 `()`로 감싸서** `({ key: 'value' })` 형태로 작성함
