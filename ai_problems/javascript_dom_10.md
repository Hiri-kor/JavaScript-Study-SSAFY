## 모범 답안 및 키워드 채점 기준표 (문항당 10점)

### 2. [ECMAScript와 JavaScript] (10점)
- **모범 답안 예시**: ECMAScript는 Ecma International이 정의한 '표준화된 스크립트 프로그래밍 언어 명세(규칙 설명서/설계도)'이며, JavaScript는 이 ECMAScript 표준 명세를 기반으로 브라우저나 Node.js 환경에서 동작하도록 구현된 '구체적인 프로그래밍 언어'이다.
- **키워드 채점 기준**:
  | 채점 기준 (핵심 키워드) | 배점 |
  |---|---|
  | ECMAScript를 **표준 명세(규칙/설계도)**로 정의 | 4점 |
  | JavaScript를 표준을 따르는 **구체적인(구현된) 프로그래밍 언어**로 정의 | 4점 |
  | **파편화 방지** 또는 **모든 환경에서 동일한 동작 보장**이라는 목적 언급 | 2점 |

### 3. [변수 선언 키워드 선택 가이드] (10점)
- **모범 답안 예시**: `const`는 재할당이 불가능하므로 ① 해당 변수가 변경되지 않는다는 코드의 의도를 명확히 할 수 있고, ② 의도치 않은 변수 값 변경으로 인한 버그를 예방할 수 있어 기본으로 사용하는 것이 좋다. 반면, 변수의 값을 의도적으로 변경해야 하는 '재할당이 필요한 경우'에만 `let`으로 전환하여 사용한다.
- **키워드 채점 기준**:
  | 채점 기준 (핵심 키워드) | 배점 |
  |---|---|
  | `const`의 특징인 **재할당 불가능(상수)** 언급 | 2점 |
  | 이유 1: **코드의 의도 명확화** (값이 바뀌지 않음을 표현) | 3점 |
  | 이유 2: **버그 예방** (의도치 않은 값 변경 방지) | 3점 |
  | `let` 사용 시점: **재할당(값의 변경)이 필요한 경우** | 2점 |

### 4. [블록 스코프와 함수 스코프] (10점)
- **모범 답안 예시**: `let`과 `const`는 **블록 스코프(block scope)**를 가지며, `var`는 **함수 스코프(function scope)**를 가진다. 블록 스코프는 `if`, `for`, 함수 등 모든 중괄호(`{}`) 내부를 기준으로 하여 블록 바깥에서 접근할 수 없지만, 함수 스코프는 오직 함수(`function`)의 중괄호 내부만을 기준으로 하므로 `if`나 `for` 블록 내부에서 선언해도 함수 바깥이 아니라면 접근이 가능하다.
- **키워드 채점 기준**:
  | 채점 기준 (핵심 키워드) | 배점 |
  |---|---|
  | `let`/`const` = **블록 스코프(block scope)** 명시 | 2점 |
  | `var` = **함수 스코프(function scope)** 명시 | 2점 |
  | 블록 스코프의 기준: **`if`, `for`, 함수 등 모든 중괄호(`{}`)** 내부 | 3점 |
  | 함수 스코프의 기준: **함수(`function`)의 중괄호**만 인정 (일반 블록 무시) | 3점 |

### 5. [DOM의 개념과 역할] (10점)
- **모범 답안 예시**: DOM(Document Object Model)은 정적인 HTML 문서(웹 페이지)를 부모-자식 관계의 계층적인 **객체 트리(Tree) 구조**로 변환하여 제공하는 모델(API)이다. 이를 통해 JavaScript 같은 프로그래밍 언어가 HTML 문서의 각 요소에 접근하여 구조, 스타일, 내용 등을 **동적으로 조작(변경)**할 수 있도록 연결해 주는 역할을 한다.
- **키워드 채점 기준**:
  | 채점 기준 (핵심 키워드) | 배점 |
  |---|---|
  | 웹 페이지(HTML 문서)를 **객체(Object)** 또는 **트리(Tree/계층) 구조**로 표현한다는 점 | 4점 |
  | 프로그래밍 언어(JavaScript)가 문서에 **접근할 수 있는 방법(API/인터페이스)** 제공 | 3점 |
  | 문서의 구조, 스타일, 내용을 **동적으로 조작(변경)**할 수 있게 함 | 3점 |

---

### 6. [DOM 요소 선택 메서드 비교] (10점)
- **모범 답안 예시**: `querySelector()`는 제공한 CSS 선택자와 일치하는 **첫 번째 요소 단 한 개**를 선택하여 **`Element` 객체**로 반환하며, 일치하는 요소가 없으면 **`null`**을 반환한다. 반면 `querySelectorAll()`은 선택자와 일치하는 **모든(여러) 요소**를 선택하여 유사 배열 형태인 **`NodeList`**로 반환한다(일치하는 요소가 없으면 빈 `NodeList` 반환).
- **키워드 채점 기준**:
  | 채점 기준 (핵심 키워드) | 배점 |
  |---|---|
  | `querySelector`: 일치하는 **첫 번째 요소 1개** 선택 | 2점 |
  | `querySelector` 반환값: **`Element` 객체** 및 없을 경우 **`null`** 반환 | 3점 |
  | `querySelectorAll`: 일치하는 **모든(여러 개) 요소** 선택 | 2점 |
  | `querySelectorAll` 반환값: **`NodeList`** 반환 | 3점 |

### 7. [DOM 요소 생성 및 삽입 원리] (10점)
- **모범 답안 예시**: `document.createElement()` 메서드는 새로운 HTML 요소를 **메모리에만 생성**할 뿐 실제 문서 트리(DOM Tree)에 연결하지 않기 때문에 화면에 보이지 않는다. 따라서 화면에 나타나게 하려면 부모 요소를 선택한 뒤 **`appendChild()`** 메서드를 사용하여 생성한 노드를 부모 노드의 마지막 자식으로 문서에 **삽입(추가)**해야 한다.
- **키워드 채점 기준**:
  | 채점 기준 (핵심 키워드) | 배점 |
  |---|---|
  | `createElement`는 요소를 **메모리에만 생성**한다는 원리 언급 | 4점 |
  | 실제 **DOM 트리(문서)에 삽입(연결)**해야 화면에 보인다는 점 언급 | 3점 |
  | **`appendChild()`** 메서드 명시 (부모 노드의 마지막 자식으로 추가) | 3점 |

---

### 8. [Node와 Element의 관계, NodeList의 특징] (10점)
- **모범 답안 예시**: `Node`는 문서 전체, 요소, 텍스트 등을 모두 포함하는 DOM의 기본 구성 단위이고, `Element`는 HTML 태그를 나타내는 `Node`의 하위 유형이다. 따라서 **"모든 `Element`는 `Node`이지만, 모든 `Node`가 `Element`인 것은 아니다(예: Text Node)."** 또한 `querySelectorAll()`이 반환하는 `NodeList`는 정적(non-live)이므로, 나중에 DOM이 변경되더라도 이전에 선택한 `NodeList`에는 **실시간으로 반영되지 않는다.**
- **키워드 채점 기준**:
  | 채점 기준 (핵심 키워드) | 배점 |
  |---|---|
  | `Element`가 `Node`의 **하위 유형**임을 설명 (`Text Node` 등 예시 포함 가능) | 3점 |
  | **"모든 Element는 Node이지만, 모든 Node가 Element는 아니다"** 명제 정확히 서술 | 3점 |
  | `NodeList`는 DOM의 추후 변경사항을 **실시간으로 반영하지 않음** 명시 | 4점 |

---

### 9. [클래스를 활용한 다크 모드 구현 원리] (10점)
- **모범 답안 예시**: 
  1단계: `document.querySelector()`를 사용하여 스타일을 적용할 웹 페이지 요소(예: `body`)를 선택한다.
  2단계: 선택한 요소의 `classList.toggle()` 메서드를 호출하여 다크 모드용 클래스(예: `'dark-mode'`)를 동적으로 추가하거나 제거한다.
  3단계: 클래스가 추가/제거됨에 따라 CSS에 미리 정의된 다크 모드 스타일이 적용되어 화면의 배경색과 글자색이 즉시 변경된다.
- **키워드 채점 기준**:
  | 채점 기준 (핵심 키워드) | 배점 |
  |---|---|
  | 1단계: **`querySelector`**로 대상 요소(`body` 등) 선택 | 3점 |
  | 2단계: **`classList.toggle()`** (또는 `add`/`remove`)로 클래스 동적 제어 | 4점 |
  | 3단계: 미리 정의된 **CSS 스타일이 적용**되어 화면이 실시간 변경됨 | 3점 |

### 10. [호이스팅(Hoisting)과 TDZ] (10점)
- **모범 답안 예시**: 변수는 **선언(Declaration) ➔ 초기화(Initialization) ➔ 할당(Assignment)**의 3단계로 생성된다. `var`는 호이스팅될 때 스코프 최상단에서 **선언과 동시에 `undefined`로 초기화**가 진행되므로 선언문 이전에 접근해도 에러 없이 `undefined`를 반환한다. 반면 `let`(과 `const`)은 **선언만 최상단으로 호이스팅**되고, 실제 코드 선언 줄에 도달할 때까지 초기화가 이루어지지 않는다. 이처럼 스코프 시작 지점부터 초기화 지점까지의 구간인 **TDZ(일시적 사각지대)**에 변수가 갇혀 있기 때문에 초기화 이전에 접근하면 `ReferenceError`(참조 에러)가 발생한다.
- **키워드 채점 기준**:
  | 채점 기준 (핵심 키워드) | 배점 |
  |---|---|
  | 변수 생성 3단계(**선언 ➔ 초기화 ➔ 할당**) 명시 | 2점 |
  | `var`: **선언과 초기화(`undefined`)가 동시에** 진행됨을 설명 | 3점 |
  | `let`/`const`: **선언만 호이스팅**되고 실제 코드 도달 시 초기화됨을 설명 | 3점 |
  | **TDZ(일시적 사각지대, Temporal Dead Zone)** 용어 및 구간 언급 | 2점 |
