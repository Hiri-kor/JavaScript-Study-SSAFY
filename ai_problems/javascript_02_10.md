### 1. 객체의 속성 확인: `in` 연산자와 `Object.hasOwn()` (10점)
객체에 특정 속성이 존재하는지 확인할 때 `in` 연산자를 사용할 수 있습니다. 하지만 실무에서는 `in` 연산자 대신 `Object.hasOwn(obj, key)` (또는 `hasOwnProperty`) 사용을 권장하는 경우가 많습니다. 그 이유를 **프로토타입** 개념을 포함하여 서술하시오.

### 2. 메서드 내부 중첩 함수에서의 `this` 바인딩과 해결책 (10점)
다음 코드에서 `myObj.myFunc()`를 실행했을 때 콘솔에 `myObj`가 아닌 `window`가 출력되는 이유를 설명하고, 이를 해결하여 `myObj`가 출력되도록 만드는 방법과 그 원리를 서술하시오.
```js
const myObj = {
  numbers: [1, 2, 3],
  myFunc: function () {
    this.numbers.forEach(function (number) {
      console.log(this)
    })
  }
}
```

### 6. 콜백 함수(Callback Function)의 정의와 활용 이유 (10점)
콜백 함수의 개념을 '실행 권한'의 관점에서 정의하고, 프로그래밍에서 콜백 함수를 사용하는 주요 이유 2가지를 강의 자료의 예시(계산기 부품 교체, 타이머 등)를 들어 서술하시오.

### 7. `forEach`, `map`, `filter`의 비교 및 불변성(Immutability) (10점)
주요 Array Helper Method인 `forEach`, `map`, `filter` 세 가지 메서드의 **목적(역할)**과 **반환 값(길이 포함)**의 차이를 비교하여 설명하고, 모던 웹 개발에서 `push` 대신 `map`이나 `filter`를 선호하는 이유를 '원본 배열(불변성)' 관점에서 서술하시오.

---

### 8. 전개 구문(`...`)을 이용한 '얕은 복사(Shallow Copy)'의 한계 (10점)
객체나 배열에서 전개 구문(`...`)을 사용하여 복사본을 만들 때 수행되는 **얕은 복사(Shallow Copy)**의 개념을 설명하고, 만약 배열 내부에 객체가 포함된 상태에서 전개 구문으로 복사한 뒤 복사본의 내부 객체 속성을 변경하면 어떤 일이 발생하는지 그 이유와 함께 서술하시오.

---

### 9. `reduce` 메서드의 동작 원리와 핵심 요소 (10점)
배열의 `reduce` 메서드가 동작하는 원리를 '눈덩이 굴리기' 비유 또는 흐름으로 설명하고, `reduce`를 구성하는 필수 요소 3가지(`acc`, `cur`, `initialValue`)가 각각 어떤 역할을 하는지 서술하시오.

---

### 10. 명령형 프로그래밍(`for...of`) vs 선언형 프로그래밍(`forEach`, `map`) (10점)
기능적으로는 `for...of` 반복문만으로도 배열 순회가 충분함에도 불구하고, Vue나 React 같은 모던 웹 프레임워크 환경에서 `forEach`나 `map` 같은 배열 헬퍼 메서드를 훨씬 더 선호하는 이유를 **명령형**과 **선언형** 프로그래밍의 차이점을 중심으로 서술하시오.

### 1번 채점 기준 (10점 만점)
* **모범 답안**: `in` 연산자는 객체 자신의 속성뿐만 아니라 **프로토타입 체인(Prototype Chain)**을 따라 부모로부터 **상속받은 속성**까지 모두 확인하기 때문에 의도치 않게 `true`가 반환될 수 있다. 따라서 상속된 속성을 제외하고 **객체 자기 자신의 고유 속성**만 정확히 확인하기 위해 `Object.hasOwn()`을 사용한다.
* **키워드 배점**:
  | 채점 기준 (핵심 키워드) | 배점 |
  | :--- | :---: |
  | **프로토타입 체인 (또는 프로토타입 / 부모 객체)** 언급 | **4점** |
  | **상속받은 속성**까지 확인하여 의도치 않게 `true`가 나올 수 있음 설명 | **3점** |
  | `Object.hasOwn()`은 **자기 자신의 고유 속성**만 확인함 설명 | **3점** |

### 2번 채점 기준 (10점 만점)
* **모범 답안**: `forEach`의 인자로 전달된 콜백 함수는 **일반 함수**로 작성되어 **단순 호출**되었기 때문에, 그 내부의 `this`는 전역 객체인 `window`를 가리킨다. 이를 해결하려면 콜백 함수를 **화살표 함수**로 변경해야 한다. 화살표 함수는 **자신만의 `this`를 가지지 않고** **상위(외부) 스코프(`myFunc`)의 `this`**인 `myObj`를 그대로 가져와 참조하기 때문이다.
* **키워드 배점**:
  | 채점 기준 (핵심 키워드) | 배점 |
  | :--- | :---: |
  | 콜백 함수가 **일반 함수로 단순 호출**되어 `this`가 **전역 객체(`window`)**가 됨 | **3점** |
  | 해결책으로 콜백 함수를 **화살표 함수(Arrow Function)**로 변경 제시 | **3점** |
  | 화살표 함수는 **자신만의 `this`가 없음** 언급 | **2점** |
  | **상위 스코프(외부 함수 `myFunc`)의 `this`**를 그대로 가져옴 설명 | **2점** |

---

### 3번 채점 기준 (10점 만점)
* **모범 답안**: JSON은 JavaScript 객체와 유사한 Key-Value 구조를 가지고 있지만 실제로는 일정한 형식을 가진 **문자열(String)**이며 특정 언어에 종속되지 않는 데이터 형식이다. 따라서 JavaScript에서 이를 다루려면 변환이 필요한데, 객체를 JSON 문자열로 변환할 때는 **`JSON.stringify()`**를 사용하고, JSON 문자열을 다시 JavaScript 객체로 변환할 때는 **`JSON.parse()`**를 사용한다.
* **키워드 배점**:
  | 채점 기준 (핵심 키워드) | 배점 |
  | :--- | :---: |
  | JSON은 객체가 아니라 **문자열(String)** 형식임 (또는 언어 독립적 데이터 포맷) | **4점** |
  | **`JSON.stringify()`**: 객체(Object) $\rightarrow$ JSON 문자열 변환 | **3점** |
  | **`JSON.parse()`**: JSON 문자열 $\rightarrow$ 객체(Object) 변환 | **3점** |

### 4번 채점 기준 (10점 만점)
* **모범 답안**: Optional Chaining(`?.`)은 왼쪽 평가 대상이 **`null` 또는 `undefined`**일 때 에러(`TypeError`)를 발생시키는 대신 뒤쪽 코드의 실행을 멈추는 **단락 평가**를 수행하고 즉시 **`undefined`를 반환**한다. 만약 논리상 반드시 존재해야 하는 루트 객체(`userData`)에까지 `?.`를 남용하면, 해당 변수에 값을 할당하지 않은 버그가 발생했을 때 에러가 나지 않고 넘어가서 **문제를 조기에 발견(디버깅)하기 어려워지기 때문**에 선택적인 속성에만 사용해야 한다.
* **키워드 배점**:
  | 채점 기준 (핵심 키워드) | 배점 |
  | :--- | :---: |
  | 참조 대상이 **`null` 또는 `undefined`**일 때 동작함 명시 | **3점** |
  | 에러 대신 평가를 멈추고(**단락 평가**) **`undefined`를 반환**함 설명 | **3점** |
  | 남용 시 반드시 있어야 할 객체의 누락(에러/버그)을 **조기에 발견하기 어려움** 설명 | **4점** |

* **모범 답안**: 네 가지 메서드 모두 **원본 배열을 직접 수정**하는 메서드이다. 이 중 `unshift()`는 배열의 맨 앞에 요소를 추가하면서 기존 요소들을 전부 **뒤로 한 칸씩 밀어야** 하고, `shift()`는 맨 앞 요소를 제거한 뒤 나머지 모든 요소를 **앞으로 한 칸씩 당겨와야(인덱스 재조정)** 한다. 따라서 배열의 길이가 클수록 연산량이 많아져 **성능이 저하**되므로 사용을 피해야 한다.
* **키워드 배점**:

  | :--- | :---: |

  | 배열의 **맨 앞**에서 요소를 추가/제거함 언급 | **2점** |
  | 배열의 **모든 요소를 한 칸씩 밀거나 당겨야 함(인덱스 이동)** 설명 | **5점** |

* **모범 답안**: 콜백 함수란 다른 함수의 **인자로 전달**되어 특정 시점에 호출되는 함수로, **함수의 실행 권한을 다른 함수에게 위임**하는 것이다. 사용하는 첫 번째 이유는 **기능의 유연성**으로, 뼈대 함수(계산기)는 그대로 두고 인자로 넘기는 부품 함수(더하기, 빼기 콜백)만 교체하여 다양한 동작을 수행할 수 있다. 두 번째 이유는 **시점 제어(비동기 처리)**로, `setTimeout`처럼 시간이 걸리는 작업이 끝난 직후 등 특정 시점에 함수가 실행되도록 등록해 둘 수 있다.

### 7번 채점 기준 (10점 만점)
* **모범 답안**: `forEach`는 단순 **순회**가 목적이며 반환 값이 없다(`undefined`). `map`은 요소를 1:1로 가공(**변형**)하여 **원본과 길이가 같은 새로운 배열**을 반환한다. `filter`는 조건이 참(`true`)인 요소만 걸러내어(**선별**) **원본보다 길이가 같거나 짧은 새로운 배열**을 반환한다. `map`과 `filter`는 **원본 배열을 변경하지 않는 불변성**을 유지하는데, 모던 개발에서는 원본이 수정되었는지 추적하는 것보다 새로운 배열로 교체되었는지 감지하는 것이 훨씬 빠르고 효율적이기 때문에 이를 선호한다.
* **키워드 배점**:
  | 채점 기준 (핵심 키워드) | 배점 |
  | :--- | :---: |
  | **`forEach`**: 단순 순회, 반환 값 없음(`undefined`) | **2점** |
  | **`map`**: 요소 변형(가공), 원본과 **길이가 같은 새 배열** 반환 | **2점** |
  | **`filter`**: 조건 선별, 원본보다 **길이가 같거나 작은 새 배열** 반환 | **2점** |
  | **불변성(원본 배열 미수정)**: 새 배열을 반환하므로 데이터 변경 감지가 빠르고 효율적임 | **4점** |

### 8번 채점 기준 (10점 만점)
* **모범 답안**: 전개 구문을 통한 **얕은 복사**는 객체나 배열의 **겉(최상위 속성/요소)만 새로운 껍데기로 복사**하고, 내부에 중첩된 객체는 실제 데이터가 아닌 **메모리 주소값만 복사(공유)**하는 방식이다. 따라서 배열 안에 객체가 들어있을 때 복사본의 내부 객체 속성을 수정하면, 같은 주소값을 바라보고 있는 **원본 배열의 내부 객체 속성도 함께 변경**되는 문제가 발생한다.
* **키워드 배점**:
  | 채점 기준 (핵심 키워드) | 배점 |
  | :--- | :---: |
  | **최상위 속성(겉)**만 새로 복사하고 **중첩 객체(속)**는 공유함 설명 | **4점** |
  | 내부 객체는 데이터가 아닌 **주소값(참조값)이 복사**됨 언급 | **3점** |
  | 복사본의 내부 객체를 수정하면 **원본 객체도 함께 바뀜** 명시 | **3점** |

### 9번 채점 기준 (10점 만점)
* **모범 답안**: `reduce`는 초기값(작은 눈뭉치)에서 시작하여 배열의 각 요소를 하나씩 순회하며 연산 결과를 누적(눈을 붙여 굴림)해 나가, 최종적으로 **하나의 결과값**(숫자, 객체, 배열 등)으로 합치는 메서드이다. 필수 요소 중 **`acc`(누적값)**는 이전 단계까지 계산된 결과를 담으며 콜백의 `return` 값이 다음 번 `acc`가 된다. **`cur`(현재값)**는 현재 처리 중인 배열 요소이며, **`initialValue`(초기값)**는 첫 순회 시 `acc`가 가질 시작 값이다.
* **키워드 배점**:
  | 채점 기준 (핵심 키워드) | 배점 |
  | :--- | :---: |
  | 배열 요소들을 줄여가며 **하나의 최종 결과값으로 집계(누적)**하는 원리 설명 | **3점** |
  | **`acc` (누적값)**: 이전 계산 결과이며 `return` 값이 다음 `acc`로 전달됨 | **3점** |
  | **`cur` (현재값)**: 현재 순회하며 처리 중인 배열의 요소 | **2점** |
  | **`initialValue` (초기값)**: 누적 계산을 시작할 때의 최초 값 | **2점** |

### 10번 채점 기준 (10점 만점)
* **모범 답안**: `for...of`는 인덱스나 `break` 등을 통해 **"어떻게(How)"** 순회할지를 하나하나 제어하는 **명령형 프로그래밍** 방식이다. 반면 `forEach`나 `map`은 콜백 함수를 통해 **"무엇을(What)"** 처리할지에만 집중하는 **선언형 프로그래밍** 방식이다. 선언형 방식을 사용하면 코드가 간결해지고 **데이터의 흐름과 목적**이 한눈에 명확히 보이며, Vue나 React, Axios(`then` 콜백) 등 모던 프레임워크 생태계가 모두 이러한 **메서드 + 콜백 함수** 구조를 지향하기 때문에 이를 선호한다.
* **키워드 배점**:
  | 채점 기준 (핵심 키워드) | 배점 |
  | :--- | :---: |
  | **명령형(`for...of`)**: "어떻게(How)" 순회/제어할지에 집중 | **3점** |
  | **선언형(`forEach`/`map`)**: "무엇을(What)" 처리할지에 집중 | **3점** |
  | 코드의 간결성 및 **데이터의 흐름(목적)이 명확**해짐 설명 | **2점** |
  | Vue, React, Axios 등 프레임워크가 **콜백 함수 기반 구조**를 사용함 언급 | **2점** |
