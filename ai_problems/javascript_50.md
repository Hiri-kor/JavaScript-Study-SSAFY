## [1~12] 데이터 타입 (원시 자료형과 참조 자료형)

**1. 원시 자료형(Primitive type)에 대한 설명으로 옳지 않은 것은?**
1) 변수에 값(value) 자체가 직접 저장된다.
2) 값의 일부를 직접 수정할 수 없는 불변(immutable) 데이터이다.
3) 다른 변수에 할당할 때 메모리 주소가 복사된다.
4) `Number`, `String`, `Boolean`, `null`, `undefined` 등이 속한다.

**2. 다음 중 참조 자료형(Reference type)에 속하지 않는 것은?**
1) `Object`
2) `Array`
3) `Function`
4) `Symbol`

**3. 다음 코드의 실행 결과로 알맞은 것은?**
```js
let text = 'apple'
text[0] = 'S'
console.log(text)
```
1) `'Spple'`
2) `'apple'`
3) `undefined`
4) `TypeError`가 발생한다.

**4. 다음 코드의 실행 결과로 콘솔에 출력될 값은?**
```js
const obj1 = { name: 'Alice', age: 30 }
const obj2 = obj1
obj2.age = 40

console.log(obj1.age, obj2.age)
```
1) `30 30`
2) `30 40`
3) `40 30`
4) `40 40`

**5. 다음 코드의 실행 결과로 콘솔에 출력될 값을 순서대로 나열한 것은?**
```js
const a = 'bar'
console.log(a.toUpperCase())
console.log(a)
```
1) `BAR`, `BAR`
2) `BAR`, `bar`
3) `bar`, `bar`
4) `bar`, `BAR`

**6. JavaScript의 `Number` 자료형에 대한 설명으로 틀린 것은?**
1) 정수와 실수의 구분이 없으며 단일 타입으로 처리한다.
2) `2.998e8`과 같은 지수 표기법을 사용할 수 있다.
3) 문자열과 `+` 연산 시 문자열이 숫자로 자동 형 변환되어 덧셈 계산된다.
4) `Infinity`, `-Infinity`, `NaN`도 숫자(`Number`) 타입의 값에 포함된다.

**7. 템플릿 리터럴(Template literals)에 대한 설명으로 옳은 것은?**
1) 작은따옴표(`' '`)나 큰따옴표(`" "`)로 문자열을 감싼다.
2) 문자열 내부에 변수나 표현식을 삽입할 때 `${expression}` 형태를 사용한다.
3) 여러 줄에 걸친 문자열을 작성하려면 반드시 `\n`을 사용해야만 한다.
4) ES5 버전부터 기본으로 지원되기 시작한 문법이다.

**8. `null`과 `undefined`를 산술 연산에 사용했을 때의 결과로 올바른 설명은?**
1) `null`은 `0`으로 취급되고, `undefined`는 `NaN`을 만든다.
2) `null`과 `undefined` 모두 `0`으로 취급된다.
3) `null`과 `undefined` 모두 `NaN`을 만든다.
4) `null`은 `NaN`을 만들고, `undefined`는 `0`으로 취급된다.

**9. 다음 중 조건문이나 반복문에서 Boolean 타입으로 자동 형 변환될 때 `true`로 변환되는 값은?**
1) `0`
2) `NaN`
3) `''` (빈 문자열)
4) `'0'` (문자열 0)

**10. 다음 중 연산의 결과가 `NaN`이 아닌 것은?**
1) `Number(undefined)`
2) `Math.sqrt(-1)`
3) `'10' + 5`
4) `'가' / 3`

**11. `NaN`에 대한 설명으로 옳은 것은?**
1) `NaN === NaN`의 평가 결과는 `true`이다.
2) `typeof NaN`의 결과는 `'NaN'`이다.
3) 피연산자 중 하나가 `NaN`인 거듭제곱 연산(`7 ** NaN`)의 결과는 `NaN`이다.
4) Boolean으로 자동 형 변환될 때 `true`로 평가된다.

**12. `typeof null`의 결과가 `'object'`로 나오는 이유에 대한 설명으로 가장 적절한 것은?**
1) `null`은 실제로 참조 자료형(Reference type)이기 때문이다.
2) 초기 JavaScript 버전에서 32비트 시스템의 하위 3비트 타입 태그가 객체와 같은 `000`이었기 때문에 발생한 버그이다.
3) ES6에서 하위 호환성을 무시하고 새롭게 추가된 표준 명세이기 때문이다.
4) 개발자가 의도적으로 빈 객체를 할당했을 때만 `null`을 사용하기 때문이다.

## [13~22] 연산자

**13. 다음 코드가 실행된 후 변수 `a`에 저장된 최종 값은?**
```js
let a = 0
a += 10
a -= 3
a *= 10
a %= 7
```
1) `0`
2) `3`
3) `7`
4) `10`

**14. 다음 코드의 실행 결과로 출력될 `x`, `y`, `m`, `n`의 값을 순서대로 바르게 나열한 것은?**
```js
let x = 3
const y = x++

let m = 3
const n = ++m

console.log(x, y, m, n)
```
1) `3 3 4 4`
2) `4 3 4 4`
3) `4 4 4 3`
4) `3 4 4 3`

**15. 다음 비교 연산의 결과 중 `false`가 반환되는 것은?**
1) `3 > 2`
2) `'A' < 'B'`
3) `'Z' < 'a'`
4) `'가' > '나'`

**16. 동등 연산자(`==`)에 대한 설명으로 틀린 것은?**
1) 두 피연산자를 비교할 때 암묵적 타입 변환을 통해 타입을 일치시킨 후 비교한다.
2) `'1' == 1`과 `0 == false`는 모두 `true`를 반환한다.
3) 두 피연산자가 모두 객체일 경우 내부의 속성값이 같으면 다른 메모리를 참조하더라도 `true`를 반환한다.
4) 직관과 다른 암묵적 타입 변환이 일어날 수 있어 주의해야 한다.

**17. 다음 중 `[1] == [1]`의 실행 결과와 그 이유로 올바른 것은?**
1) `true` – 배열 안의 요소가 둘 다 숫자 `1`로 같기 때문이다.
2) `true` – 암묵적 타입 변환을 통해 문자열 `'1'`로 변환되어 비교되기 때문이다.
3) `false` – 배열은 동등 연산자로 비교할 수 없어 에러가 발생하기 때문이다.
4) `false` – 내용은 같지만 메모리의 서로 다른 객체를 바라보고 있기 때문이다.

**18. 다음 중 일치 연산자(`===`)를 사용한 표현식의 결과가 `true`인 것은?**
1) `'1' === 1`
2) `0 === false`
3) `null === undefined`
4) `'hello' === 'hello'`

**19. 일반적인 JavaScript 프로그래밍에서 동등 연산자(`==`) 대신 일치 연산자(`===`) 사용을 권장하는 가장 주된 이유는?**
1) 연산 속도가 훨씬 빠르기 때문이다.
2) 암묵적 타입 변환을 하지 않아 예측하지 못한 결과를 방지하고 엄격한 비교를 할 수 있기 때문이다.
3) 객체 내부의 값까지 깊은 비교(deep comparison)를 자동으로 수행해주기 때문이다.
4) `===` 연산자만 조건문(`if`) 내부에서 사용할 수 있기 때문이다.

**20. 다음 논리 연산자의 단축 평가 결과로 출력될 값을 순서대로 바르게 짝지은 것은?**
```js
console.log(1 && 0)
console.log(4 && 7)
```
1) `false`, `true`
2) `0`, `7`
3) `1`, `4`
4) `0`, `4`

**21. 다음 논리 연산자의 단축 평가 결과로 출력될 값을 순서대로 바르게 짝지은 것은?**
```js
console.log(1 || 0)
console.log(0 || 1)
console.log(4 || 7)
```
1) `1`, `1`, `4`
2) `1`, `1`, `7`
3) `true`, `true`, `true`
4) `0`, `0`, `7`

**22. 다음 중 논리 연산자에 대한 설명으로 옳지 않은 것은?**
1) `&&`는 AND 연산, `||`는 OR 연산, `!`는 NOT 연산을 수행한다.
2) `!true`의 결과는 `false`이다.
3) `0 && 1`을 실행하면 왼쪽 피연산자가 `0`(falsy)이므로 오른쪽을 평가하지 않고 `0`을 반환한다.
4) 논리 연산자의 반환 값은 언제나 `true` 또는 `false`의 Boolean 타입이다.

## [23~26] 조건문

**23. `if` 조건문에 대한 설명으로 올바른 것은?**
1) 조건 표현식에는 반드시 비교 연산자가 포함되어야 한다.
2) 조건 표현식의 결과값을 Boolean 타입으로 변환한 후 참/거짓을 판단한다.
3) `else if`는 한 `if` 문 안에서 최대 1번만 사용할 수 있다.
4) `else` 뒤에도 소괄호 `()`로 조건식을 반드시 작성해야 한다.

**24. 다음 코드의 실행 결과로 출력되는 문자열은?**
```js
const name = 'customer'
if (name === 'admin') {
  console.log('관리자님 환영해요')
} else if (name === 'customer') {
  console.log('고객님 환영해요')
} else {
  console.log(`반갑습니다. ${name}님`)
}
```
1) `관리자님 환영해요`
2) `고객님 환영해요`
3) `반갑습니다. customer님`
4) 아무것도 출력되지 않는다.

**25. 삼항 연산자(`condition ? expression1 : expression2`)에 대한 설명으로 틀린 것은?**
1) 세 개의 피연산자를 가지는 연산자이다.
2) `condition`이 참(truthy)으로 평가되면 `expression1`이 반환된다.
3) `condition`이 거짓(falsy)으로 평가되면 `expression2`가 반환된다.
4) 복잡한 다중 조건 로직일수록 `if` 문 대신 삼항 연산자를 중첩해서 사용하는 것이 가독성에 항상 좋다.

**26. 다음 코드의 실행 결과 `message`에 할당되는 값은?**
```js
const age = 20
const message = (age >= 18) ? '성인' : '미성년자'
```
1) `true`
2) `false`
3) `'성인'`
4) `'미성년자'`

## [27~36] 반복문

**27. `for ([초기문]; [조건문]; [증감문]) { // 코드 블록 }`의 동작 순서로 올바른 것은?**
1) 초기문 → 코드 블록 → 증감문 → 조건문
2) 초기문 → 조건문 평가(참) → 증감문 → 코드 블록
3) 초기문 → 조건문 평가(참) → 코드 블록 → 증감문
4) 조건문 평가(참) → 초기문 → 코드 블록 → 증감문

**28. 다음 `while` 반복문이 종료되었을 때 마지막으로 콘솔에 출력된 숫자와, 반복문 종료 직후 변수 `i`의 값으로 올바른 것은?**
```js
let i = 0
while (i < 6) {
  console.log(i)
  i += 1
}
```
1) 마지막 출력: `5`, 종료 후 `i`: `5`
2) 마지막 출력: `5`, 종료 후 `i`: `6`
3) 마지막 출력: `6`, 종료 후 `i`: `6`
4) 마지막 출력: `6`, 종료 후 `i`: `7`

**29. `for...in` 반복문에 대한 설명으로 옳은 것은?**
1) 반복 가능한(iterable) 객체의 값(value)을 순회한다.
2) 객체의 열거 가능한(enumerable) 속성(property)의 키(key)에 대해 반복한다.
3) 배열의 요소들을 인덱스 순서대로 안전하게 보장하며 순회할 때 가장 권장된다.
4) 일반 객체(`{ a: 1, b: 2 }`)에 사용하면 `TypeError`가 발생한다.

**30. 다음 코드의 실행 결과로 올바른 것은?**
```js
const capitals = {
  korea: '서울',
  japan: '도쿄',
  china: '베이징'
}
for (const capital of capitals) {
  console.log(capital)
}
```
1) `'korea'`, `'japan'`, `'china'`가 순서대로 출력된다.
2) `'서울'`, `'도쿄'`, `'베이징'`이 순서대로 출력된다.
3) `TypeError: capitals is not iterable` 에러가 발생한다.
4) `undefined`가 3번 출력된다.

**31. 배열 `const arr = ['a', 'b', 'c']`에 대해 `for (const i in arr) { console.log(i) }`를 실행했을 때 출력되는 값과 그 타입은?**
1) `'a'`, `'b'`, `'c'` (문자열)
2) `0`, `1`, `2` (숫자)
3) `'0'`, `'1'`, `'2'` (문자열)
4) `undefined`

**32. 배열을 순회할 때 `for...in`을 사용하지 않고 일반 `for` 문이나 `for...of`를 사용하는 이유로 틀린 것은?**
1) `for...in`은 배열의 요소 값이 아니라 인덱스를 반환하기 때문이다.
2) `for...in`은 특정 순서에 따라 인덱스를 반환하는 것을 보장할 수 없기 때문이다.
3) `for...in`은 배열의 프로토타입에 추가된 속성이나 정수가 아닌 이름의 속성까지 순회할 수 있기 때문이다.
4) 배열에 `for...in`을 사용하면 문법 오류(`SyntaxError`)가 발생하여 코드가 실행되지 않기 때문이다.

**33. 다음 코드의 출력 결과를 순서대로 나열한 것은?**
```js
const arr = ['a', 'b', 'c']
for (const elem of arr) {
  console.log(elem)
}
```
1) `0`, `1`, `2`
2) `'a'`, `'b'`, `'c'`
3) `['a', 'b', 'c']`
4) `TypeError` 발생

**34. 반복문에서 변수 선언 키워드 `const`의 사용 가능 여부에 대한 설명으로 올바른 것은?**
1) `for (const i = 0; i < 5; i++)`는 정상적으로 작동한다.
2) `for...in`과 `for...of`에서는 매 반복마다 변수가 재할당되므로 `const`를 사용할 수 없다.
3) `for...in`과 `for...of`에서는 매 반복마다 새로운 바인딩이 생성되므로 `const`를 사용해도 에러가 발생하지 않는다.
4) `while` 반복문의 조건 변수는 반드시 `const`로 선언해야 한다.

**35. `while`, `for`, `for...in`, `for...of` 반복문 내부에서 `let`이나 `const`를 사용했을 때 형성되는 스코프는?**
1) 전역 스코프 (Global scope)
2) 함수 스코프 (Function scope)
3) 블록 스코프 (Block scope)
4) 렉시컬 스코프가 적용되지 않음

**36. 객체 `const fruits = { a: 'apple', b: 'banana' }`에서 `for (const property in fruits)`를 사용할 때, `'apple'`과 `'banana'`라는 값에 접근하기 위한 올바른 표현식은?**
1) `property`
2) `fruits.property`
3) `fruits[property]`
4) `fruits(property)`

## [37~50] 함수 (정의, 매개변수, 전개 구문, 화살표 함수)

**37. JavaScript의 함수(Function)에 대한 설명으로 옳지 않은 것은?**
1) 모든 함수는 `Function` object이며 참조 자료형에 속한다.
2) `return` 문이 없거나 `return` 뒤에 값이 없으면 함수는 `null`을 반환한다.
3) 함수를 변수에 할당하거나 다른 함수의 인자로 전달할 수 있다.
4) 함수 선언식과 함수 표현식 두 가지 주요 방식으로 정의할 수 있다.

**38. 함수 선언식(Function declaration)과 함수 표현식(Function expression)을 비교한 설명으로 틀린 것은?**
1) 함수 선언식은 함수 전체가 호이스팅되어 선언 전에 호출할 수 있다.
2) 함수 표현식은 선언 전에 호출하면 에러가 발생한다.
3) 함수 표현식에는 함수 이름이 없는 '익명 함수'를 사용할 수 있다.
